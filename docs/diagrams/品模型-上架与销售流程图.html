范围：品 = listing 去掉店铺之后的"商品"；Etsy 上卖的每一档，库里必有预设档案（实物 SKU / 组合配方 / 定制占位），上架只引用、不现场新建（定稿 §3.6）。库存永远只在 实物 SKU × 仓库。

① 概念分层：实物 / 档案 / 品 / 店铺×品（listing）/ 图 / SEO

例：金属打火机，含 颜色[红,蓝] 与 包装[普装,精装] 两路档；精装打火机 = 组合配方（机+精装盒）。店 1 图 A、店 2 图 B —— 同一个品、同一批货。

素材库（图源）扒图链接/自拍/AI/授权，带来源标记；一个链接 = 一组图
店铺 × 品 = Etsy listing（每店一份"样子"） 店1 listing：图集 A（图A）· SEO A · 价 · 启用档[红✓蓝✓精装✗]
店2 listing：图集 B（图B）· SEO B · 价 · 启用档[红✓蓝✗精装✓]
SEO / 标题 / 价格 挂这里，不挂货
▲ 店×品 = 一个 Etsy listing；图/SEO/价/启用哪些档，每店各管各的，互不打架
品：金属打火机（商品主档，全局唯一，跨店共享） 建档单位。定义变体档 → 每档指向一个"本地档案"：
红 → LTR-RED（实物）　蓝 → LTR-BLU（实物）　普装 → LTR-PLN（实物）　精装 → COMBO-LTR-DLX（组合配方）
底图模板（默认图）挂品级，店未覆盖时自动继承
▲ 每档必指向已预设档案 —— "库里有规划，不许现场造"
实物 SKU（有库存）LTR-RED 红打火机
编号/成本/采购源
实物 SKU（有库存）LTR-BLU 蓝打火机
编号/成本/采购源
组合配方（无库存）COMBO-LTR-DLX 精装打火机
BOM：打火机×1 + 精装盒×1
库存穿透到子件
定制占位（无库存）CUSTOM-BQ 定制花束
接单生产，内容记订单
▲ 库存、流水、扣减只认这一层 —— 不管多少店多少图，仓库就这些实物
仓库实物红机 ×N　蓝机 ×N　精装盒 ×N
（精装打火机不是一件货，它只是档案）

② 上架一个 listing 的流程（从素材到 Etsy 在售）

阶段 A 建档 → B 开店准备 → C 校验与上架 → D 在售后续。红线：系统不写 Etsy（上架动作 = 人工抄录任务单），本机永不直连 Etsy。

1建档 A素材库选素材链接记录「建档」→ 该链接整组图预载（或从素材库弹层跨链接混选）
2建档 A建品 + 变体框架品名（链接 desc 建议）→ 填变体维度（≤3，如 颜色:[红,蓝] × 包装:[普装,精装]）→ 系统按维度自动展开全部档位草稿
3建档 A每档挂"本地档案"红→选实物 LTR-RED；精装→选组合配方 COMBO-LTR-DLX（预设 BOM）；没有的档案先建档（编号查重 + 禁逗号斜杠校验）→ 不允许空映射
4建档 A底图 + 状态从素材勾选图挂品级「底图模板」→ 补成本/编号 → 状态 = 建档中 → 在售
5开店 B选店铺 → 生成 listing 草稿店铺×品 = 一条 listing：默认继承品底图（图 A），个别店可整套覆盖（图 B）；勾选本店启用哪些档
6开店 BSEO 初稿（v0.8 联动）按"店×品"生成标题/描述/tag 初稿 → 提案 → 人改后用
7校验 C上架前机器校验每个启用档都有本地档案？编号唯一/格式合法？图齐？→ 不通过 = 按钮灰，缺什么提示什么（§3.6：库里没有的 SKU 禁止上架）
8上架 C上架任务单（TM）出任务单：标题/描述/13 tag/每档该填的 SKU 编号/图包 → 运营照着抄进 Etsy 后台（变体 SKU 框必须填表里高亮的编号 = 订单对账钥匙）
9上架 C回填 listing_id人工把 Etsy listing_id 贴回 → 平台在售档就位 → 系统拉 listing 自动核对：变体数/SKU 是否填对/图数
10在售 D此后改价/换季 tag/下架 = 在"店×品"上操作；订单回来按 sku 直对上（见下节）

③ 销售一单的流程（Etsy 订单进来到账平）

订单行带 transaction.sku（= 上架时填的本地档案编号）→ 三种命中，三种走法。库存为 0 不阻塞销售（接单采购模式），但每笔变动都留流水。

1订单回流Etsy 订单 → 行级 sku 命中本地档案（两段式：先实物/组合/定制判断）
🟢 命中实物 SKULTR-RED 直扣
  • 库存：红机 所在仓库 -1（按 SKU×仓库）
  • 出库单：红打火机 ×1
  • 够不够都卖（接单采购），不足触发补货建议
🟣 命中组合配方COMBO-LTR-DLX BOM 展开
  • 展开：打火机 -1、精装盒 -1（子件各自所在仓库扣）
  • 出库单/拣货校验：机 ×1 + 精装盒 ×1 —— 系统判断"有没有精装盒、盒里有没有打火机"就在这里
🟣 命中定制占位CUSTOM-BQ 转人工
  • 不扣库存（本来就没有）
  • 按订单详情（内容记在订单行）生成接单生产/采购任务 → 人工处理
4库存流水必留每笔变动落流水：时间/类型（销售扣减·采购入库·报损·调整·退货入库）/数量/操作人/关联单号 → 对不上可追溯（谁、何时、为何）
5对账闭环订单行 ↔ 扣减记录 ↔ 流水 ↔ 库存余额 四方对得上 = 一单销完；对不上 = 进对账差异，可查流水定位

④ 用模型跑 8 个边界场景（压力测试）

场景模型怎么答
金打火机：店 1 图 A、店 2 图 B 在卖同一个品、同一个档；图 A/B 是两店 listing 各自的图集（店×品），货不裂、库存不裂
同款红/蓝两色一 listing同一品、两个档（颜色维度）；每档一个实物 SKU、独立库存/成本 —— 金一个库存、银一个库存，互不掺和（§3.7）
精装/普装作为 listing 变体普装 → 实物 SKU；精装 → COMBO- 组合配方（机+盒），出库展开校验 —— 不用新建一件叫"精装打火机"的货
打火机+烟 的套餐 listing（跨品）不是品内档位，是卖法层组合：COMBO-LIGHTER-CIG 虚拟 SKU + BOM（引用两品下的实物 SKU，v0.8）—— 品层不吞卖法层
两店卖同一品、卖不同档子集品不变；店 1 listing 启用[红✓蓝✓]，店 2 启用[精装✓] —— 启用档是店×品的属性
库存为 0 的档照卖接单采购模式：库存不影响销售；售出后触发采购建议/备货提醒，数字照记（0）
定制花束（CRM 那种）品级勾「定制」→ CUSTOM-BQ 占位：无库存、成本可空、接单生产，内容记订单详情
一图含两个主体（打火机+烟）且都要卖不能共用：建档勾图时打「待拆」标记暂不挂图集；改图（COMFYUI，后置单独做法）拆好后再挂 —— v0.7 不做裁剪
同店同品开两个 listing（A/B 测试）开放项：一期不确认；店×品 = 一个 listing，双 listing 留扩展位，不阻塞本期

⑤ 结论：品是帮了忙，还是添了乱？

品帮了什么（消掉三个没品时的坑）

  • 店 1/店 2 的"打火机"不再互不相识 —— 品 = 唯一的打火机，两店 listing 都指向它，货只建一次（v1 文档痛批的"同一棵树 12 条物料"不会发生）
  • 图/SEO 有明确挂点 = 店×品，店间图差异天然分开不打架
  • 「精装打火机」这类半组合档有处安放：指向预设组合配方，BOM 展开扣

品的边界（守住 = 纯简化器，越界 = 添乱）

  • 品 不管库存（只在 实物 SKU×仓库）、不管价格（店×品）、不管SEO/图（店×品，品只挂默认底图）、不管店
  • 品只回答三个问题：这是个什么商品？有几个档？每档对应仓库里哪样货（或哪个配方/定制）？
