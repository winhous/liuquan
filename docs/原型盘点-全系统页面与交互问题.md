# 原型盘点：全系统页面清单与交互问题（第一稿）

> 阶段 0 产出 · 2026-09-04 · 用途：全系统原型重构轮的现状基线
> 数据来源：`web/app.py` 路由 + `web/templates/` + `MODULES` 导航定义（真实代码，非凭印象）
> 性质：**第一稿**，供产品经理逐条批注；批注后升为定稿，作为 IA 重排与原型设计的输入。
> 标注：`[视觉]` 观感 / `[交互]` 交互与信息架构 / `[一致]` 全局一致性 / `[流程]` 缺原型确认环节所致

## 〇、结论先行

- 系统有 **6 个一级入口、23 个可访问页面/动作面**，其中 **5 处为占位**（工作台、ERP 三项、风格指南术语表）。
- 页面**数量已不少但无统一产品框架**：导航分三级混用、占位枝挂在真菜单里、跨模块入口语义错位、表单页与列表页版式各写各的。问题不是某页丑，而是**没有一层「骨架」被定义过**——这正是本轮的靶心。
- 根本流程缺口：**页面原型从未先于开发被评审确认**（铁律只到详设字段级，页面级靠子代理自由发挥）→ 本轮把它补上：原型 → PRD → 开发。

**全局菜单问题**
1. 一级菜单 6 个，其中 ERP/SEO/设置/CRM 有子级，任务中心/工作台没有——**导航承载模型不统一**（有的点一级直达、有的要先展开子级才能点到真实页面）。刚才建档演示就撞上：点「货品建档」点不到，得先点开「ERP」。 [交互]
2. 三个 ERP 占位入口 href 全部相同（/modules/erp），**用户点进三次看到同一张"建设中"**。 [交互]
3. 「风格指南术语表」占位还占着 AI 设置的位置，导航里先看到"空承诺"。 [交互]

## 三、交互问题观察（第一稿，等你批注）

**IA / 导航层**
1. 系统口号是「AI 大管家主动盯店、循环往复」，但**首屏是任务列表、工作台空置**——产品叙事缺"每天一打开看什么"的锚点页。 [交互]
2. 扒图 + 素材库 + 图库浏览器（AI 打标后）本质是**一条"素材资产"主线**，现分别塞在 SEO 与建档页内，无统一"素材中心"心智。 [交互]
3. 建档（货档案）与"店×listing 上架"（v0.9）的关系、库存三块（进销存/补货建议/异常预警/生产库存）的职责边界，导航上无法体现，需要一张**目标 IA** 来定。 [交互]

**页面层**
4. 建档表单页承载过多：商品名 + 多档行(每行 8 字段) + 规格折叠 + BOM 折叠 + 图库选图 + 搜索，**一页多任务**，新手易迷路；规格/BOM 靠 display:none 折叠，展开开关语义弱。 [交互][视觉]
5. 列表页（任务/客户/档案/素材）各自为政：筛选器位置、状态徽章样式、分页样式、空态文案不统一。 [一致]
6. 全站无统一**空态引导**（无数据时多为空白表格）。 [视觉][交互]
7. 详情页信息密度无层级：档案详情把"编号/代号/规格徽章/图片/操作"平铺，无分组视觉节奏。 [视觉]
8. 操作反馈依赖整页跳转 + 顶部 msg，**无轻量 toast/行内反馈**，批量操作（如上架多档）无进度感。 [交互]
9. 表单校验错（如编号撞重）回跳后**已填内容与错误提示的对应关系弱**（顶部红条）。 [交互]
10. 登录只有角色下拉无账号概念——原型形态可以，但权限心智要在目标 IA 里提前画位（v1.0）。 [交互][流程]

**一致性层**
11. 图标库/按钮层级/颜色语义（成功绿/危险红/警示黄）无书面规范，各模块自由发挥。 [一致]
12. 同样的"状态"在任务(五态)、档案(active/inactive)、库存(结存/流水)里呈现方式不同。 [一致]

**流程层（本轮要修的根）**
13. 所有页面**没有经过"原型→你确认→开发"的门**，页面是子代理按字段级详设直接渲染的——字段对、产品错。 [流程]
