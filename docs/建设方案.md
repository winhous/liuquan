## 总体技术底座（各版本共用，一次说清）

### 代码仓库结构

```text
liuquan/
├── engine/                  AI 引擎（L2，独立可测，无业务概念）
│   ├── core/                状态机 / Policy 门禁 / 检查点 / 审计 / 队列消费
│   ├── registry/            工序与链的 YAML 声明 + schema 校验 + loader（拒载）
│   └── workers/             AI 工序实现（<域>/<工序>/run.py + schema.py + config/）
├── models/                  Pydantic Model：工序输出契约 + 四契约（Event/Context/Action/Task）
├── web/                     业务应用（L1，FastAPI + Jinja2 + HTMX）
│   ├── tm/ crm/ erp/ seo/ scrape/
│   ├── engineapi/           引擎对外三接口
│   └── templates/ static/
├── migrations/              Alembic（业务库 + 引擎库两套）
├── tests/                   单测（fake LLM）+ 端到端
├── scripts/                 部署 / 数据迁移 / 运维脚本
├── deploy/                  systemd 单元 + 部署说明
└── docs/                    文档（本目录）
```

### 数据库（PG16 单实例双 database）

```text
业务库 liuquan：          schema: crm / tm / erp / seo / scrape
引擎库 liuquan_engine：   引擎任务 / 步骤 / 检查点 / 审计 / 配额 / 调度表
外部只读：                NocoBase PG 的 v_* 视图（只读账号连接）
```

### 引擎任务运行模型（贯穿所有版本）

```text
触发（人工API/事件/定时）
  -> scheduler 建 engine_task（含链定义）入队
  -> runner 消费（SELECT ... FOR UPDATE SKIP LOCKED）
  -> 每工序跑状态机：INIT -> REASON(AI) -> ACT -> OBSERVE -> VERIFY -> 终态
  -> 每相位转换前写 checkpoint；每次 LLM 调用写 audit
  -> 链完成：产出 TaskProposal / 分析结果，通知 TM
```

### 四契约（Business AI Contract，业务模块接入引擎的唯一接口）

| 契约 | 方向 | 含义 | 例子 |
|---|---|---|---|
| Event | 业务 -> 引擎 | "我发生了什么" | 库存低于阈值、收到新消息 |
| Context | 业务 -> 引擎 | "我能给你看什么"（数据供给声明） | 该 SKU 近 30 天销量/现库存/交期 |
| Action | 引擎 -> 业务 | "你可以建议我做什么"（引擎声明产出类型） | 创建采购任务、生成翻译 |
| Task | 引擎 -> TM | "帮我派活给人" | 一条带来源追溯的任务提案 |

新业务模块接入 = 在 `models/contract/` 登记这四样 + 工序声明。引擎代码零改动。⚑ 四契约的字段级规范是 v0.1 详设的第一项。

## v0.1 引擎地基

**做什么**：引擎最小内核，命令行可跑通一个工序，全程可审计可恢复。

### 实现内容

| # | 内容 | 说明 |
|---|---|---|
| 1 | 状态机 | 5 相位（INIT/REASON/ACT/OBSERVE/VERIFY + 终态 DONE/FAILED/PAUSED）；相位转换代码写死；每工序一次状态机实例 |
| 2 | PydanticAI 接入 | `output_type` 即输出契约；模型实例走配置（`text -> deepseek-chat`）；重试/超时/降级策略 ⚑ |
| 3 | 工序注册表 | `engine/registry/`：工序 YAML（id/domain/inputs/outputs/model/风险/version）+ 链 YAML（工序序列）；loader 全册 schema 校验，缺字段拒载启动失败 |
| 4 | 审计 | 每次 LLM 调用记录：输入摘要/输出/token 数/耗时/耗时毫秒/模型/工序/任务 id，落引擎库 |
| 5 | 检查点 | 每相位转换前落库；崩溃后重启从最后检查点续跑（不重烧 token） |
| 6 | 队列消费（雏形） | `engine_task` 表 + SKIP LOCKED 取任务；本版仅命令行触发入队 |
| 7 | 演示工序 | 1 个端到端工序（建议：echo-结构化，输入文本输出固定 Model）+ 1 个真调 DeepSeek 的工序（建议：翻译雏形，为 v0.3 探路） |
| 8 | CLI | `liuquan-engine run <task>` / `resume <task>` / `verify` / `registry-check` |
| 9 | lint 工具 | `engine/lint` 三规则（P1 业务词黑名单-词表从注册表自动生成 / P2 凭据端点零容忍 / P3 契约），每规则配反向测试；挂入 verify 成为四绿之一（规范 R10 四层防线的机器层） |

### 怎么做（关键设计）

- 引擎不依赖 web，可独立进程运行；对 DeepSeek 的调用只在 `engine/core/llm` 一处
- 硬编码四层防线在本版立住（承广成 2026-08-18 审计返工的教训）：架构层（工序只碰 inputs/config/原语）从第一行代码就守；lint 工具与首批工序同步落地，不事后补；演示工序的规格值全部走 config/，作为外置范例
- 单测 fake LLM：stub PydanticAI Agent 类，断言 prompt 组装与输出类型校验路径；不依赖网络（规范 R12）
- 反向测试：注册表缺字段拒载、绕过注册表直调工序函数被拒、模型 id 内联进 run.py 被 lint 拦
- 审计内容脱敏：对话全文不进日志，进审计表（受控可查），日志只留摘要 ⚑ 规则详设定

### 做完是什么样子

```bash
$ liuquan-engine run "translate" --input '{"text":"hello"}"
task e-001 created, chain: translate
  [INIT]    policy ok (domain=demo, risk=read)
  [REASON]  pydantic-ai -> deepseek-chat, 320 tokens, 1.2s
  [ACT]     write result
  [VERIFY]  fields ok
  [DONE]    1.4s total
$ liuquan-engine audit e-001        # 查输入输出/token/耗时
```

### 验收标准

- [ ] 命令行提交工序任务，状态机全相位走完到 DONE
- [ ] 注册表缺字段，引擎拒启动（有反向测试）
- [ ] 审计表可查：每次调用的输入/输出/token/耗时
- [ ] REASON 中途 kill 进程，重启后从检查点续跑，前段 AI 结果不重烧
- [ ] 全量单测绿（fake LLM，零网络依赖）
- [ ] lint 三规则生效：故意违规样本（业务词/密钥/直连 SQL）各被拦截（反向测试覆盖）
- [ ] 换模型只改配置文件不改代码（测试覆盖）

## v0.2 TM + 引擎接通

**做什么**：AI 建议自动变任务，人工处理完回流；Web 骨架立起来。

### 实现内容

| # | 内容 | 说明 |
|---|---|---|
| 1 | 双 database | 业务库 liuquan（tm schema 先行）+ 引擎库；Alembic 两套迁移 |
| 2 | 队列完整化 | runner 常驻进程消费 engine_task；并发上限；失败重试策略 ⚑ |
| 3 | TM 数据模型 | task（目标/负责人/截止/状态/来源追溯）、task_proposal（AI 提案 + 风险级）、task_event（状态流水）。**细则已拍板（2026-08-27，2026-08-28 修订：取消 P0-P3 优先级分级**——无分级标准、AI 分级不准确、人工难界定，逾期标红保留、「逾期自动升级」随分级取消；后续有标准则 AI 按标准分级再议**）**：负责人按角色（运营/采购/管理员）指派，AI 提案按工序域带默认角色可改；截止手填 + AI 建议可改；状态五态 open/in_progress/done/void/blocked（blocked=等物料/等回复）；循环任务不在 TM 做，统一交 v0.4 定时链。**任务生成细则（决策 16，2026-08-28：任务生成双通道（AI 生成 + 人工输入）；任务来源 = 业务系统（CRM/ERP/SEO 等）+ 任务系统自身，task.domain 标来源域（列表标来源徽章）；AI 提案审核依据强制展示（每条 evidence 类型+ref_id+原文摘录+查看入口），AI 可引用数据受链白名单封闭，100% 禁止幻觉（机器校验拒落））。任务生命周期细则（决策 17，2026-08-28：两种结束方式（完成/作废）都必须人工回复，不回复不能结束；派生新任务不代表原任务结束；权限 v0.2 不做、将来必须引入完善权限系统（精确到人和数据，同页面不同人看到不同任务数量与内容），架构留位；同事件防重（同业务对象+同建议类型，未完成任务一直挂着不自动清理）；任务生成后有权限人员可编辑；逾期一直提醒 + 列表筛选（筛选条件后定，一定有））** |
| 4 | TaskProposal 审核流 | **全部提案进审核页人工批/驳**（2026-08-27 业务拍板，不设代码自动通过）；风险级仍由代码规则标注（域 + 动作类型查表），作展示与排序用；**审核页强制展示提案依据（evidence 类型+ref_id+原文摘录 + 查看入口 + 审计兜底）**（决策 16） |
| 5 | FastAPI 骨架 | 路由骨架 + Jinja2 模板基座 + 共享密码登录 + 三角色标签（管理员/运营/采购） |
| 6 | 引擎三接口 | POST /api/engine/tasks、GET /api/engine/tasks/{id}、GET /api/engine/registry |
| 7 | 状态回流 | 任务完成后结果事件回引擎（为 v0.4 事件触发的闭环留位） |
| 8 | 演示链 | 一条"工序链 -> 提案 -> 任务 -> 处理 -> 回流"的端到端演示链 |
| 9 | 工作台 | 一级菜单，**当前版本无内容**（统计等内容后续在定；决策 15：统计数据一定会做，方向确认后按需纳入后续版本） |

### 怎么做（关键设计）

- web 只经三接口碰引擎，不 import engine 内部模块（规范 R4 的工程边界）
- 提案风险判定是**代码规则**（域 + 动作类型查表），不是 AI 自评（规范 R5）
- 登录从简：共享密码 + 角色 cookie；会话过期/角色权限点后续版本按需加

### 做完是什么样子

浏览器打开 `http://<host>:<port>` 登录 -> 首页是任务清单页 -> 触发演示链 -> 提案出现在"待审核"栏（附提案详情与来源）-> 人工批准后入清单（标"AI 建议"来源）-> 勾选完成 -> 任务事件落库，引擎可见。

### 验收标准

- [ ] 触发工序链 -> 产出提案 -> 全部进审核页 -> 人工批准后成任务
- [ ] 人工处理任务 -> 状态回流，引擎可查
- [ ] 三接口可用（curl 可演示）
- [ ] 登录与角色标签生效
- [ ] runner 崩溃自动重启（systemd）后队列不丢任务
- [ ] 全量单测 + 四绿

## v0.3 CRM 平移

**做什么**：EOMS 已验证的 CRM 链路在刘全跑通，体验不倒退（基线 5.8s），广成电脑关机不影响。

> 2026-08-28 需求对齐修订（决策 19-28）：待办衔接 = CRM 页内确认即建 tm.task；**EOMS 存量数据不迁移**（取消第 5 项）；飞书通知确认做；客户删除平移保留；跟进候选并入 todo-generate；**任务只按 domain 区分（决策 24），客户 = CRM 域任务的关联对象**；任务标签机制（25）；业务写入接口化（26）；任务流转机制 + 自然语言入口（27/28）。

### 实现内容

| # | 内容 | 说明 |
|---|---|---|
| 1 | 四工序平移 | chat-translate / snapshot-update / todo-generate / customer-reply-draft；逻辑参考广成同名 SKILL，调用层换 PydanticAI（删手写 normalize） |
| 2 | 风格指南配置 | 承接广成 customer-chat-extract / customer-reply-draft 的 config/（风格指南/术语表），改配置不改代码 |
| 3 | crm schema | customer / message / snapshot / todo_candidate；滚动快照机制平移；**todo_candidate = AI 待办候选暂存（带 evidence），确认后转 tm.task（决策 19）** |
| 4 | CRM 页面 | 沿用 EOMS 活档案布局（决策 22 确认）：客户列表（筛选/搜索/分页/重名/删除）+ 详情三行布局（快照通栏/收件粘贴+回复台/时间线）+ 任务确认弹窗（依据强制展示，决策 16）；客户详情页任务卡 = 「domain=crm 且 source.customer_id=X」的过滤视图（**任务只按 domain 区分，决策 24**）。**「对话翻译」子页 = 独立翻译工具（决策 23）**：粘贴任意文本→选语言→翻译→译文可复制、不落客户档案，可选「归入某客户」；**客户详情「粘贴对话」即历史记录入口（决策 23）**：与正常对话同一入口正常走链（翻译+快照+待办），AI 理解上下文滚动快照，message_time 不标 |
| 5 | ~~EOMS 数据迁移~~ | **取消（决策 20）**：存量数据不要了，不写迁移脚本，从零录数据 |
| 6 | 飞书通知 | 确认做（决策 21）：飞书群自定义机器人 webhook 卡片；`.env` 配 `LIUQUAN_FEISHU_WEBHOOK_URL`；CRM 待办确认生成 TM 任务时推任务卡片；未配置不阻塞 |
| 7 | 异步化改造 | 页面提交即返回任务 id，轮询显示进度，取代 EOMS 的 300s 同步阻塞 |
| 8 | 客户删除 | 平移保留（决策 22）：列表行删除 + 级联清对话/快照/该客户任务 + 二次确认 |
| 9 | 任务标签 + 流转机制 | TM 通用能力（决策 25/27/28，CRM 待办衔接使用）：`tm.task` 加 `tags`（开放标签，AI 建议+人工可改）；「下一步」区 = AI 建议（默认值）+ 人同意/改派/忽略 + **自然语言入口**（AI 解析为结构化指令→人确认→执行，解析模糊澄清不猜测，未接入域明确提示）；分歧留痕 task_event |
| 10 | 业务写入接口化 | 架构改造（决策 26）：业务域写入统一走接口（不区分 AI/人，只校验正确性即入库）；crm 域按接口化新建；tm 转交器由直连业务库改为 HTTP 调 web 业务写入接口 |

### 怎么做（关键设计）

- 链定义：`chat-translate -> snapshot-update -> todo-generate`（回复台按需单独触发单工序链）；跟进候选并入 todo-generate 产出（决策 22）；**独立翻译工具触发单翻译链（决策 23，v0.1 crm_translate 雏形升级）**
- 每工序一个 output Model（ChatTranslateResult 等），字段对齐广成交付物结构
- 端到端耗时目标 <= 6s：翻译/快照/待办三工序串行 DeepSeek 调用，预估 3-5s；超标的优化手段（并行化/上下文裁剪）预留 ⚑
- **待办衔接**（决策 19/24）：todo-generate 产出候选落 `crm.todo_candidate`（带 evidence，ref_id 走链数据白名单 = Context provider 声明，禁幻觉三件套）→ 客户详情页确认弹窗（每条候选带依据原文摘录，勾选确认 = 人工审核）→ 落 `tm.task`（domain=crm, source_type=ai, **source 带 customer_id + candidate_id 追溯**，决策 24 关联对象）
- **任务标签**（决策 25）：候选带 suggested_tags（AI 判断任务类型）→ 确认落库写入 tm.task.tags；人工编辑可改；列表/详情标签徽章
- **业务写入接口化**（决策 26）：业务域写入服务 = 只接受数据（不区分 AI/人）→ Pydantic 校验 + 业务规则校验 → 入库；引擎侧消费者经 HTTP 调业务写入接口，**引擎进程不持有业务库连接串**
- **流转机制**（决策 27/28）：tm.task 存 AI 下一步建议（默认值）；「下一步」区 = 同意建议 / 改派（角色/标签）/ 忽略 + **自然语言输入框**（如「流转到 ERP 库存」→ 引擎意图理解工序解析为结构化指令 Model → 展示解析结果 → 人确认 → 执行；模糊→澄清提示；未接入域→明确提示不可执行并记录意图）；分歧留痕 task_event（ai_suggested vs human_chose）
- 飞书通知封装为 web 侧轻量模块（HTTP POST JSON 卡片），URL 读 `.env`（P2 合法来源），失败静默不阻塞页面

### 做完是什么样子

员工在 CRM 页粘贴一段英文对话 -> 点"翻译" -> 2 秒内开始逐条出译文 -> 快照更新 -> 待办候选列出（带依据引用）-> 确认入库 -> 待办出现在 TM 清单（标来源 CRM）-> 飞书收到任务卡片。想单纯翻译时（产品描述/邮件/任意文本），打开「对话翻译」子页粘贴即出译文可复制，需要存档时点「归入某客户」。

## v0.4 定时闭环 + 设置页（配置地基）

**做什么**：①先立配置地基——settings 表 + 设置页（除权限外，决策 34/35/36），让所有参数都从设置里读，杜绝硬编码继续滋生；②系统第一次不需要人触发自己干活——定时自动检查、任务自动就位 TM。

### 导航与交互形态（决策 36 修订）

- **导航**：一级「设置」下每个设置项 = **独立二级菜单**：AI 设置（分组）/ 店铺管理 / 定时任务 / 通知配置 / 系统参数
- **AI 设置 = 分组标题（不可点，纯分组，四个字）**，其下挂**真正的叶子菜单**：API 密钥 / 模型选择 / 风格指南术语表（Tabler nav-group 实现，成本与三级导航相同；用户评估拍板：不用 TAB 页）——**v0.4 只做 API 密钥，其余叶子占位**，后续慢慢加（加"模型选择"= 加一个叶子菜单 + 一个页面，不动其他）
- **独立提交机制（适用于所有设置）**：每个设置块 = 独立小表单 + 独立提交按钮 + 独立接口（如 `POST /settings/ai/api-key`、`POST /settings/shops/{id}`、`POST /settings/schedule/{id}`、`POST /settings/params/{key}`）；提交后 **HTMX 局部刷新该块**（不整页、不牵连其他块）；settings 表按 key 存，每次提交**只更新本块涉及的 key（原子更新不动其他 key）**——改 API 只提交 API，避免"一次提交全量设置"

### 实现内容

| # | 内容 | 说明 |
|---|---|---|
| 1 | settings 表（配置地基） | 键值对配置表（key/value/说明/更新时间）；**读配置先查表、表无回退默认（文件/.env）**，老配置不删平滑迁移；统一读取封装（`get_setting(key, default)`），业务代码一律经它取参数 |
| 2 | 设置页 ① 店铺管理 | 店铺表（名称/备注/启用停用）+ 管理页（增删改/启停，**每条独立存**）；CRM source_shop 下拉候选改读店铺表 |
| 3 | 设置页 ② AI 设置（分组下叶子：API 密钥 / 模型选择 / 风格指南） | **v0.4 只做 API 密钥叶子**：DeepSeek key 填写入口（**底层仍存 .env，R20 密钥不进数据库**——页面是写 .env 的友好壳，独立提交只写这一个 key）；模型选择/风格指南叶子占位后续加 |
| 4 | 设置页 ③ 定时任务模块 | 定时链清单页面化：列表（链名/触发时间/上次运行/下次运行/开关）+ 新增/启停/改时间（**每条链独立存/独立开关**）；驱动下方调度器 |
| 5 | 设置页 ④ 通知配置 | 飞书 webhook 页面化（决策 21 留账，现 .env）+ 通知开关（独立提交） |
| 6 | 设置页 ⑤ 系统参数 | 跟进天数/逾期天数/列表每页条数/定时链默认时间等**现有硬编码全量搬 settings 表**（现 `FOLLOW_UP_DAYS = 5` 硬编码在 crm_store.py；客户列表 page_size=20 写死；**每个键独立存/独立提交**） |
| 7 | 定时触发底座（引擎） | schedule 表（定时链清单：链 id/cron/开关/上次/下次/状态）+ 调度器（到点触发链入队）+ 去重（同一业务对象当天不重复触发，决策 17 防重语义复用）；事件触发/配额记账**不做**（决策 33：用不到就不做，留底座扩展位） |
| 8 | 首批定时链 1 条 | CRM 客户超 N 天未跟进提醒：每天自动跑 → 找出超 N 天无动静客户（N 从 settings 表读）→ 生成提醒任务进 TM（domain=crm，带客户关联与依据） |

> ~~登录密码、角色~~：v0.4 不做（决策 36 撤销决策 35 之⑥，随 v0.7 权限系统；门禁暂维持现状）。

### 做完是什么样子

导航出现「设置」一级菜单，下面五个二级菜单（AI 设置分组/店铺管理/定时任务/通知配置/系统参数）。AI 设置下是叶子菜单（API 密钥/模型选择/风格指南），当前只有 API 密钥可进，填完点提交**只保存这一项**、只刷新这一块。店铺/定时/系统参数同理，改哪个提交哪个，互不牵连。每天早上 7 点（定时任务页可改）系统自动跑 CRM 未跟进检查 → 3 个超过 5 天（系统参数页可改）没跟进的客户 → 「跟进提醒」任务已在 TM 清单（标来源 CRM）→ 同一客户当天重复触发只生成一次。之后写任何新功能，参数一律 `get_setting()` 取，不再硬编码。
