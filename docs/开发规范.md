# 刘全开发规范

> 刘全开发的唯一准则源与验收标准。只写可判定的规矩（能检查过/不过），不写架构叙事。
> 架构见概设 v0.3 与 `CLAUDE.md`；版本进度见 `docs/版本规划.md`；改动记 `docs/变更日志.md`。

## 一、AI 可控（最高原则，凌驾于所有其他规矩）

**R1 AI 只在指定相位出现。** AI 参与仅限工序的 REASON 相位（及 ACT 的内容生成环节）。状态转换、下一步走向、数据库写入、越域访问，全部代码写死，AI 无权决定。

**R2 输出即类型。** 工序输出必须是 Pydantic Model（PydanticAI `output_type`）。校验失败由框架自动 re-ask，禁止手写 `_normalize_*` 容错函数，禁止"格式不对直接 failed"。

**R3 三层校验缺一不可。** AI 输出落库前依次过：PydanticAI 类型校验 -> 业务规则代码校验（条数对得上、引用存在、数值合理）-> 审计落盘（可抽查）。

**R4 唯一跑法。** 一切 LLM 调用走引擎（工序 -> PydanticAI -> DeepSeek）。业务代码（web 层）禁止直调 LLM API、禁止 import pydantic_ai、禁止出现 api_key / base_url / 模型 id 字符串。模型配置只在引擎配置一处。

**R5 AI 不碰账本。** AI 产出的是**建议**（TaskProposal）或**分析结果**，写业务库的永远是人审核后的代码路径（2026-08-27 起：全部提案人工审，无代码自动通过路径）。

## 二、工序纪律

**R6 工序契约。** 工序 = `run(inputs, engine) -> OutputModel`。取输入 -> 组原语 -> 返回交付物。不碰数据库连接、不 import LLM SDK、不直接 subprocess、不为缺失上游写死假数据。

**R7 声明式注册，拒载。** 每个工序在注册表 YAML 登记（id / 域 / 输入输出类型 / 模型能力 / 风险等级 / version）。loader 启动时全册 schema 校验，缺字段或非法抛错、引擎不起。未登记的工序不可执行，无旁路。

**R8 域隔离。** 工序只能读所属域（crm / tm / erp / seo / scrape）的上下文。越域需在声明中显式列出，且经 Policy 放行、审计记录。

**R9 风险分级。** 动作四级：只读 < 建议 < 写业务数据 < 执行事务。只读免审；**全部 AI 提案（TaskProposal）进审核页人工批/驳**（2026-08-27 业务拍板，不设代码自动通过）；执行事务必须人工审批。审批状态可暂停（PAUSED），人工恢复续跑。

**R10 硬编码治理（四层防线）。** 工序代码不得出现：外部端点/URL、绝对路径、业务规格数字（如"13 标签"）、兜底业务话术、店铺数据、密钥。业务值外置优先级：任务参数 > 工序 `config/` > 注册表声明 > 链声明。允许：提示词内联、模型能力类型引用、中性解析代码。

四层防线（缺一层即防线不完整）：

1. **架构层（根本）**：工序只能碰 inputs / config/ / engine 原语。数据库连接、API key、URL 在结构上写不进工序代码（R6 的工程边界就是本层的载体）。
2. **去处层**：禁止之外必须给去处。业务规格进 `config/`（如 SEO 标签数），模型绑定进引擎配置，连接参数进注册表声明。改规格 = 改配置，不改代码。
3. **机器层（lint，四绿之一）**：`engine/lint` 三规则强制扫描：
   - P1 业务词黑名单：run.py 命中业务词即违规。**词表从注册表 YAML 自动生成**（工序声明的域/业务词自动入表），不手工维护
   - P2 凭据与端点：api_key / base_url / `sk-` 前缀 / 绝对路径 / IP / 具体模型 id，**零容忍**（红线级）
   - P3 契约：run.py import 业务模块、直接 SQL、subprocess 即违规
4. **守门层**：每条 lint 规则配反向测试（故意违规样本必须被拦），防止校验器本身改坏。

**检查项：** run.py 出现 URL / 绝对路径 / 业务常量 / 兜底文案 / 密钥 -> 违反。lint P1/P2/P3 任一红 -> 违反。lint 规则无反向测试 -> 违反。

**R11 模型引用化。** 工序声明模型能力类型（如 `text`），配置绑定具体实例。换模型只改配置。工序代码出现具体模型 id（`deepseek-chat` 等）即违规。

## 三、质量与留痕

**R12 测试不烧钱，桩注入式。** 单测用桩 LLM（fake Agent，承广成桩模式），零网络、零真 token。桩一律**构造注入**（LLM 调用封装暴露注入参数），禁止 monkeypatch 内部。**桩只许住在 `tests/`**：生产目录（engine/models/web/scripts）出现桩类名或固定假交付数据 = lint 违规（P3 契约纪律执法）。真模型冒烟只在发版前跑关键链路（见 `开发流程.md` ⑥）。

**R13 四绿守门。** lint 0 违规、注册表一致性全过、全量单测通过、verify 通过。任一不绿 = 改动未完成，不得标完成、不得发版、不得进下一单元。存量红项先修再推进。

**R14 改动必留痕。** 凡改动工序/规范/架构/依赖，在 `docs/变更日志.md` 追加一条「因为…所以…」。只增不减。

**R15 工序级版本。** 每个工序在注册表声明 `version`（x.y.z）。工序改动 = bump + 变更日志一条 + git 落地。run.py + 输出 Model + config/ 是一个回滚单元。

**R16 发版必落地。** 版本 = 系统能力里程碑（见版本规划）。发版必须 git tag + commit，验收标准全达成才发，不允许"部分完成的版本"，不允许版本悬空。

### R12 实施细则：测试桩规范（承广成桩模式，可判定）

**注入点唯一**：对 LLM 的调用只经 `engine/core/llm/` 封装，封装暴露 agent 工厂注入参数（或 PydanticAI `FunctionModel`）。测试构造桩传入，被测代码对桩无感知。

**桩家族五件套**（每个 AI 工序的单测必须覆盖前两种，后三种按工序声明覆盖）：

| 桩 | 行为 | 验证的路径 |
|---|---|---|
| 标准桩 | 返回合法 output（结构对齐工序 output Model） | 正常全链路（INIT->DONE） |
| 捕获桩（Capturing） | 记录收到的 prompt | prompt 组装正确：context 拼入、模板变量替换、config 注入 |
| 失效桩（Unavailable） | 抛连接异常/超时 | 三级重试降级到 FAILED，error 带显式原因，不产半成品 |
| 坏输出桩（BadOutput） | 返回结构不符 output Model | PydanticAI re-ask 路径 + 耗尽后 FAILED |
| 空输出桩（Empty） | 返回空结构 | VERIFY 断言拦截（宁失败不假成功） |

**测试数据规则：**

1. fixture 只住 `tests/fixtures/`，按工序分目录；样本结构必须对齐注册的 Model（加载即类型校验，结构漂移测试自然红）
2. 业务样本可用真实历史数据但须脱敏（客户姓名/地址/单号替换）
3. 测试断言只断**结构、路径与状态**，不断言业务内容细节（业务内容会变，结构是契约）
4. 真模型冒烟（发版前）：每链跑 1 次真 DeepSeek，断审计落库，不断业务结论

**判定方式**：`grep -rn "class.*\(Fake\|Stub\)" engine/ models/ web/ scripts/` 有结果 = 违规；被测代码里出现桩 import = 违规；测试文件 monkeypatch `pydantic_ai` 内部 = 违规。

## 四、安全红线（违反即事故）

**R17 永不写 Etsy。** 刘全任何代码不调用 Etsy 卖家写 API。上架/改价 = 人工 + 任务单模式。

**R18 永不写 NocoBase。** 只读 v_* 视图。对 NocoBase 库执行写 SQL 即违规。

**R19 三机铁律。** 本机/办公机代码永不直连 Etsy API。AWS（34.228.44.95）是唯一 Etsy 出口，AWS -> 阿里云链路一根线不动。

**R20 密钥纪律。** 密钥只存 `.env`（不入 git）；`.env.example` 只留变量名；日志和审计不明文记录密钥与对话全文。

## 验收检查表（工序开发完成前逐项核对）

- [ ] 输出是 Pydantic Model，无手写归一化（R2）
- [ ] run.py 无直接 SQL / SDK import / subprocess（R6）
- [ ] 注册表已登记，缺字段拒载有测试覆盖（R7）
- [ ] 无旁路 LLM 调用（R4）
- [ ] 域声明与越域声明正确（R8）
- [ ] 风险等级与审批路径正确（R9）
- [ ] 无业务值硬编码：四层防线齐备（架构边界 / 外置去处 / lint 三规则全绿 / 反向测试在）（R10）
- [ ] 无具体模型 id（R11）
- [ ] 单测全过（桩注入式，零网络）（R12）
- [ ] 桩覆盖：标准桩 + 捕获桩必有；失效/坏输出/空输出按声明覆盖（R12）
- [ ] 生产目录无桩类/假数据；测试数据住 tests/fixtures/ 且结构对齐 Model（R12）
- [ ] 四绿全绿（R13）
- [ ] 变更日志已追加（R14）
- [ ] 工序版本已 bump（R15）
- [ ] 无 Etsy 写 / 无 NocoBase 写 / 密钥未入 git（R17-R20）
