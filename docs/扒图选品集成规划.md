# 扒图与选品上架集成规划（v0.5 扒图重做）

> 状态：**草案待用户确认** ｜ 依据：三工作台方案 v3（`/home/winhous/project/erp/etsy-orders/docs/新品上架三工作台方案_v3.md`）+ 用户 2026-09-03 拍板（废飞书入口 / 粘贴刘全立即·定时扒 / 产物进 ERP 选品卡 / ERP 管流程刘全供 AI / 工序取舍先对比广成）
> 本规划回答：扒图要做什么内容、怎么做、以及和 SEO 优化 / AI 任务 / 图片处理 / ERP 上架 / SKU 怎么集成。

## 1. 用户真实业务全貌（三工作台 v3：选品→运营→采购）

```
选品岗（找货·洗图·建档）          运营岗（照单上架）            采购/生产岗（备货）
───────────────                   ──────────────              ───────────────
闲鱼/小红书看到货
   │
   ▼
【选品卡】（v3 在 ERP 建）
   来源链接/原图入库 → 系统体检（分辨率/水印）
   → Google 查重（人工，系统留记录）
   → AI 换背景定稿（ERP 侧：ChatGPT/Photoroom/通义万相）
   → 建档：全新=新建本地 SKU / 已有=绑货品主档（不裂物料）
     套装必配 BOM；变体 Style 绑本地 SKU
   → 标题/描述（DeepSeek 出初稿，人改）← 刘全 SEO 能力落点
   → Tag 池勾 13 个
   → 定价助手建议售价
   ▼
【派发上架】→ 上架任务单（ERP 左 + Etsy 右，一键复制）
   → 回填 Listing ID → 系统校验 → 平台在售档绑本地 SKU
   ▼
订单 → 平台 SKU → 本地 SKU（有图/库存/成本）→ 备货建议 → 采购单
```

**v3 三条铁律**：①物料 = 仓库里一件货，多店 = 多张在售档，不裂物料；②图从 ERP 带去 Etsy，新品不再扒回；③Etsy 变体 SKU 框填本地 SKU（订单自动对上的钥匙）。

## 2. 扒图在整条链里的定位（重做后的角色）

**扒图 = 选品素材采集环节**：闲鱼/小红书链接 → 图片 + 商品元数据（描述/标签/作者）→ 进刘全图库（scrape.image_file）→ **供 ERP 选品卡引用/入卡**。

- **不是**：网页贴链接下载完就完事（v0.5 现状，无去向，用户"几乎不能用"）
- **而是**：素材采集 → 图库 → 选品卡/体检/选品建议 → 建档（SKU）→ SEO 初稿 → 上架任务，**一条链走通**

## 3. 入口重做（用户拍板：废飞书入口）

| 项 | 设计 |
|---|---|
| 入口 | 刘全扒图页（保留改进 v0.5 页面，样式已 Tabler 化）：粘贴链接 → **立即扒** / **加入定时队列** |
| 立即扒 | 粘贴 → 提交 → scrape_suggest_chain 立即跑（下载→体检→建议），结果回显图库 + 选品建议进 TM 提案 |
| 定时扒 | 复用 v0.4 schedule 底座：扒图链接列表存设置键（如 `scrape.link_queue`），定时链（如每日 08:30）批量扒 → 新增落图库 → 结果进 TM 任务/飞书通知（可选） |
| 历史 | 批次记录（batch_id）+ 图片网格（v0.5 已有）+ 状态（运行中/完成/失败） |
| 多链接 | 一次粘贴多行 = 一个批次批量扒（v0.5 JS 已支持 urls 多行） |

## 4. 扒图工序取舍（结论待子代理对比报告补全，见 §A 附录）

- 刘全 v0.5 image_download/xhs/xianyu/http_image connector 为「照搬广成」实现（技术摸底报告确认）；子代理正在逐行对比广成 run.py + xhs/xianyu connector vs 刘全实现，输出功能差异表（视频支持?/元数据完整度/选择器/错误处理）→ 本规划以对比结论定：完全保留 / 补齐 / 改造
- 原则：**引擎能力已四绿（A47/A48 通过），不推倒重来**；差距在入口体验、产物去向、业务链衔接

## 5. 与各系统集成设计（核心）

### 5.1 SEO 优化（标题/描述初稿 → v3 建档环节）
- 现状：seo_optimize 工序已四绿（titles 3-5/tags≤13/描述重写，playbook 外置）
- 集成：选品卡建档时「标题/描述」= **刘全 seo_optimize 出初稿**（输入：扒图元数据 + 可选图片 + 目标关键词）→ 提案进 TM → 人改后用于上架
- 落点：扒图页/选品卡上「生成 SEO 初稿」按钮 → seo_optimize_chain → 结果回显（v0.5 已建 seo_optimize_chain + 提案流）

### 5.2 AI 任务（TM 提案审核流，决策 12/16 延续）
| 触发 | 提案/任务 | domain |
|---|---|---|
| 扒图完成 | 图片体检异常（分辨率不足/水印）→ 建议换图 | scrape |
| 扒图完成 | 选品建议（product_suggestion，元数据+AI） | scrape |
| 体检发现下滑 | 优化建议（seo_healthcheck 已建） | seo |
| 建档请求 | 标题/描述初稿（seo_optimize） | seo |
| 上架请求 | 上架任务单（人工确认后进 TM，运营执行） | seo/scrape |

### 5.3 图片处理
| 处理 | 归属 | 状态 |
|---|---|---|
| 图片体检（分辨率/水印） | 刘全 image_inspect（已建） | ✅ v0.5 |
| 图库（scrape.image_file 元数据） | 刘全（已建） | ✅ v0.5 |
| 缩略图展示 | 刘全（/scrape/thumbnail 已建） | ✅ v0.5 |

| Google 查重 | **人工**（v3：ERP 给按钮，阿里云出口不适合撞 Google） | 刘全给「打开搜图」入口记录 |

### 5.4 ERP 上架（三工作台流程在 ERP，刘全 AI 供数）
- 刘全**不建选品工作台 UI、不建 SKU 主档、不写 Etsy**（红线：一期不写 Etsy；ERP 流程归 ERP）
- 刘全对 ERP：①扒图产物/图库 → **进选品卡**（衔接方式待拍板 §7-A）②SEO 初稿/选品建议/定价建议 → 选品卡字段 ③上架任务单（刘全 TM 任务 = 人工执行入口）
- ERP 对刘全：NocoBase 只读 v_* 视图（v0.6 才接）——**本规划阶段选品卡衔接优先用「人工/导出」而非直写 ERP**（红线：刘全一期不写 NocoBase，决策 6 ERP 只读）

### 5.5 SKU（建档在 ERP，v3 铁律）
- 刘全**不建 SKU 主档**（v3：全新=新建本地 SKU / 已有=绑货品主档，在 ERP 做）
- 刘全可给 **SKU 编码建议**（AI：按品类/款式规则生成候选，人工采纳）——待拍板是否纳入
- 变体设计（Style 绑 SKU）/ BOM / Tag 池 / 定价：均在 ERP（v3），刘全 AI 建议喂字段

## 7. 待拍板点（确认规划时一并定）

- **A. 扒图产物进选品卡的衔接方式**：
  ① 人工：刘全扒图页出「图包/批次」，选品卡人工上传（最快，符合"ERP 管流程"）
  ② 刘全直写 ERP 选品表（需破"一期不写 NocoBase"红线，另行授权 + 技术方案）
  ③ 刘全出结构化数据（链接/图片路径/元数据 JSON），选品卡一键导入（折中）
- **B. SKU 编码 AI 建议**要不要做（v3 建档时给候选 SKU）
- **C. 定时扒的默认时间/频率**（如每日 08:30；链接队列在设置页维护）
- **D. 定价建议**是否纳入（依赖 ERP 视图，可能放 v0.6 接数据后）
- **E. 换背景/图片生成**是否后续在刘全做（v3 规划在 ERP，先不做）

## 8. 分阶段实施（用户确认规划后细化）

- **阶段 1 入口与队列**：扒图页改「立即/定时」+ 链接队列设置键 + 定时扒链（复用 schedule 底座）——v0.5 补丁

## 10. 技术整改项（v0.5 扒图实现断点，重做范围——2026-09-03 排查确认）

| # | 断点 | 现状 | 重做方案 |
|---|---|---|---|
| T1 | 扒图页 JS 调 `/api/tasks/create`（404） | 批 4 JS 写错路径，后端无此路由（已补 `/scrape/run`、`/scrape/suggest` 临时路由） | 重做时统一页面提交接口（表单/JSON 一致） |

| T4 | 多链接批量 | ImageDownloadInput 单 url；链步骤单输入输出，批量下载无模型支撑 | 输入 urls[]，工序循环下载，输出 packs[]（image_inspect 按 pack 收集） |
| T5 | 立即/定时 | 仅手动点开始 | 立即 + schedule 定时链（链接队列键 `scrape.link_queue`） |
| T6 | 产物去向 | 图库与选品卡无衔接 | 按拍板 A（人工图包/直写/导入）接通三工作台 |
| T7 | 页面体验 | 已修导航/布局/JS 路由（commit ddd1442/a9963ae/临时） | 重做时按新交互（立即/定时/批次状态）重排 |
