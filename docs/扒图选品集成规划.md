## 1. 用户真实业务全貌（三工作台 v3：选品→运营→采购）

```
选品岗（找货·洗图·建档）          运营岗（照单上架）            采购/生产岗（备货）
───────────────                   ──────────────              ───────────────
闲鱼/小红书看到货
   │
   ▼
【选品卡】（v3 在 ERP 建）
   来源链接/原图入库 → 系统体检（分辨率/水印）
   → Google 查重（人工，系统留记录）
   → AI 换背景定稿（ERP 侧：ChatGPT/Photoroom/通义万相）
   → 建档：全新=新建本地 SKU / 已有=绑货品主档（不裂物料）
     套装必配 BOM；变体 Style 绑本地 SKU
   → 标题/描述（DeepSeek 出初稿，人改）← 刘全 SEO 能力落点
   → Tag 池勾 13 个
   → 定价助手建议售价
   ▼
【派发上架】→ 上架任务单（ERP 左 + Etsy 右，一键复制）
   → 回填 Listing ID → 系统校验 → 平台在售档绑本地 SKU
   ▼
订单 → 平台 SKU → 本地 SKU（有图/库存/成本）→ 备货建议 → 采购单
```

**v3 三条铁律**：①物料 = 仓库里一件货，多店 = 多张在售档，不裂物料；②图从 ERP 带去 Etsy，新品不再扒回；③Etsy 变体 SKU 框填本地 SKU（订单自动对上的钥匙）。

## 2. 扒图在整条链里的定位（重做后的角色）

**扒图 = 选品素材采集环节**：闲鱼/小红书链接 → 图片 + 商品元数据（描述/标签/作者）→ 进刘全图库（scrape.image_file）→ **供 ERP 选品卡引用/入卡**。

- **不是**：网页贴链接下载完就完事（v0.5 现状，无去向，用户"几乎不能用"）
- **而是**：素材采集 → 图库 → 选品卡/体检/选品建议 → 建档（SKU）→ SEO 初稿 → 上架任务，**一条链走通**

## 3. 入口重做（用户拍板：废飞书入口）

| 项 | 设计 |
|---|---|
| 入口 | 刘全扒图页（保留改进 v0.5 页面，样式已 Tabler 化）：粘贴链接 → **立即扒** / **加入定时队列** |
| 立即扒 | 粘贴 → 提交 → scrape_suggest_chain 立即跑（下载→体检→建议），结果回显图库 + 选品建议进 TM 提案 |

## 4. 扒图工序取舍（定稿：保留下游 + 搬回广成连接器细节 + 修通链路，不推倒）

**结论来源**：`docs/技术摸底-扒图工序对比-广成vs刘全.md`（子代理逐行对比，2026-09-03）。**总体判断：刘全 v0.5 扒图 = 广成「骨架化照搬 + 下游升级」，xhs 照搬是坏的、闲鱼兜底大幅缩水、业务链 6 断点；重做 = 保留下游设计、搬回广成连接器细节、修通链路，而非推倒重来。**

### 4.1 完全保留（刘全优于广成的部分）
下游设计（体检+选品→提案审核，方向正确）、ImagePack/SuggestionInput Pydantic 契约 + worker.yaml 声明式、http_image 通用图连接器 + xhslink/2.taobao 别名、页面多链接批量贴 + 徽章/缩略图/批量选品交互、reason:none 零 token 工序。

### 4.2 需补齐（照广成原样搬回）
- **xhs 两处硬伤**：①子进程调用 `from main import download` 必 ImportError（vendor main.py 无此函数）→ 改广成 `from source import XHS` + `XHS(work_path=..., folder_name='', folder_mode=True, image_download=True, video_download=False, record_data=True, download_record=False, image_format='JPEG')` + `extract(url, download=True)`；②元数据 SQL 用错表/列（note_data+英文列不存在）→ 改 `SELECT "作品描述","作品标签","作者ID" FROM explore_data WHERE "作品ID"=?`（recorder.py DATA_TABLE 实锤）
- **xhs 补齐**：差集计数（before/after 只数本次新增）、未落盘检查（paths 空 → ok=False +「xsec_token 过期，重新取最新分享链接」提示）、vendor 完整度检查（source/__init__.py）
- **闲鱼全套搬回**：11+6 套主图/详情选择器、`_harvest_all_imgs` naturalWidth≥100 尺寸过滤、9 类 URL 过滤关键词、`_DEAD_PAGE_KEYWORDS` 失效页删垃圾图、全局 90s deadline（非 set_default_timeout）、networkidle 优先降级 domcontentloaded、标题 page.title 去后缀+desc+h1 三路、卖家 window.__INITIAL_STATE__ 两路
- **元数据降级标注**：ok=True 时 note 记降级原因（db-missing/no-title/...），上层可区分真读到 vs 降级空

### 4.3 需改造（刘全自己的断点，见 §10）
链 input 契约统一（拆两链）、image_file 落库 + 补 A47/A48 验收、EngineContext 注入 biz_client（或 image_inspect 改走 provider）、product_suggestion 诚实化（真接 LLM 或改 reason:none）、定时触发落地。

> 视频/价格：两边都不支持/无先例，本规划不做（业务未排期）。

## §A 附录：广成 vs 刘全扒图工序对比（子代理报告，2026-09-03 完成）

**结论**：刘全 v0.5 扒图 = 广成「骨架化照搬 + 下游升级」，xhs 照搬是坏的（调用必 ImportError + 元数据 SQL 表/列名全错）、闲鱼兜底大幅缩水（11+6 套选择器 → 自创 3+3，无过滤/失效页/全局截止）、业务链 6 断点（链 input 契约、image_file 落库、biz_client 注入、product_suggestion 假 LLM、定时、JS 端点）。重做 = **保留下游设计 + 搬回广成连接器细节 + 修通链路**，不推倒。

- 广成下游唯一消费者 = feishu-write（扒图产物 → 飞书多维表格人工记录，无 AI 加工）
- 刘全下游 = 体检 + 选品提案 → TM 审核（更完整的产品闭环，方向正确但未跑通）
- 视频两边都不支持（广成显式 video_download=False）；价格两边都没有（闲鱼未扒价格，需新增则无广成先例可抄）

完整对比表见 `docs/技术摸底-扒图工序对比-广成vs刘全.md`（含行级证据：vendor main.py 无 download 函数、recorder.py DATA_TABLE 落库结构实锤、闲鱼选择器列表等）。
