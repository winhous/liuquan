# 刘全数据底层逻辑：实物 · 物料 · 卖法三层模型

> **状态：已确认（2026-09-03 与用户逐点讨论拍板）** ｜ 优先级：**最高**——这是整个刘全系统数据的底层地基
> 后续 SEO 优化、ERP 对接、SKU 建档等一切设计**必须基于本规则**（引用本文件，不得另立模型）
> 配套交互白板：`docs/diagrams/白板-业务全流程.html`（讨论中逐步绘制，本文件是其文字版定稿）

## 0. 一句话

**实物（仓库里的货）≠ 物料（SKU 档案）≠ 店铺（通用实体：Etsy 店/闲鱼店/未来平台）≠ 卖法（可售单元/Listing）**，分层各管各的；
**一套图 = 1 个 SKU × 1 个店铺**（图不挂在 SKU 上，挂在"SKU × 店铺"上）；**库存记在实物/物料上，不分店**；**组合卖法 = 配方表（BOM），不占独立库存**；**系统里没有的 SKU 禁止上架**。

## 1. 分层模型（核心）

```
┌─────────────────────────────────────────────────────────────┐
│ ⑤ 卖法层（可售单元 / Listing）      ← SEO、上架在 店铺×卖法 维度 │
│    单卖打火机 / 单卖烟 / 套餐(打火机+烟) / 套餐(+火柴)…          │
│    · 组合卖法 = 配方表（BOM）：引用下面物料，各 ×N               │
├─────────────────────────────────────────────────────────────┤
│ ④ 图集层                         ← 一套图 = (SKU × 店铺)       │
│    SKU-打火机×店铺A → A的打火机图集 ｜ SKU-打火机×店铺B → B的图集 │
│    · 主图/轮播/详情/多角度都属于同一套图                        │
├─────────────────────────────────────────────────────────────┤
│ ③ 店铺层（通用实体）              ← 不分平台，结构相同            │
│    店铺A(Etsy) / 店铺B(Etsy) / 闲鱼店 / 小红书店 / 未来平台店    │
├─────────────────────────────────────────────────────────────┤
│ ② 物料层（SKU 档案，全局唯一）     ← 名称/规格/成本不分店          │
│    打火机 SKU / 烟 SKU / …                                     │
├─────────────────────────────────────────────────────────────┤
│ ① 实物层（仓库库存）              ← 库存数量只记这一层，不分店     │
│    打火机 ×100 / 烟 ×100 / …                                   │
└─────────────────────────────────────────────────────────────┘
```

### 各层职责（明确分工，不越界）

| 层 | 管什么 | 不管什么 |
|---|---|---|
| ① 实物层 | 库存数量、实物 | 图、SEO、卖法、店铺 |
| ② 物料层 | SKU 档案（名称/规格/成本，全局一份） | 库存、组合、上架、店铺差异 |
| ③ 店铺层 | 店铺实体（平台字段 + 店铺维度组织） | 库存、物料内容 |
| ④ 图集层 | 每套图（= SKU × 店铺） | 库存、SEO |
| ⑤ 卖法层 | 卖法的 SEO、上架内容（店铺 × 卖法维度） | 库存、实物 |

## 2. 库存规则（用户 2026-09-03 拍板）

### 2.1 库存分开存

- **库存分开存**：仓库里有什么就存什么——打火机 100、烟 100，**每样一行**
- **组合卖法不占库存**：套餐（打火机+烟）**不是仓库里的一件货**，不单独记库存
- **卖套餐 = 按配方扣减**：卖 1 个套餐 → 打火机 -1、烟 -1（BOM 展开），仓库账始终只有实物那几行
- **为什么必须这样**：
  1. 符合仓库实物（不存在"套餐"这堆货）
  2. 组合会爆炸（5 个单品任意组合 = 2⁵=32 种卖法，组合建库存会失控）——分开存，组合随便加，库存零变化
  3. 与三工作台 v3 铁律一致：「物料 = 仓库里一件货，不裂物料」

### 2.2 接单采购模式（用户 2026-09-03 澄清：核心业务模式）

- **绝大多数商品不备货**（库存为 0），**部分商品会备货**（有库存）
- **库存不影响销售**：缺货不阻塞上架、不阻塞出售（不是"有货才卖"模式）
- **售出后做采购**：卖出后触发采购（补货），属于"接单采购"模式
- 库存数字仍然记录：备货的记数量，不备货的记 0；库存的作用 = 备货提醒、售出后采购触发、报表统计

### 2.3 多仓库（用户 2026-09-03 确认需要）

- **仓库是多维度的**：目前有**代发仓**和**自己的仓库**，未来可能更多
- 库存按「SKU × 仓库」记录（如：打火机 代发仓 0 / 自有仓 100）
- 组合卖法扣减时按仓库策略执行（具体策略后续定）

### 2.4 库存流水（用户 2026-09-03 确认需要）

- 库存**不能只有数字，必须有流水**：每笔变动记录（时间/类型/数量/操作人/关联单号）
- 变动类型至少包括：销售扣减 / 采购入库 / 报损 / 调整 / 退货入库
- 库存对不上时可按流水追溯（谁、何时、为何）

### 2.5 库存状态不影响销售（总结）

- 上架/出售不校验库存（接单采购模式：绝大多数不备货、部分备货）
- 库存的作用：备货提醒、售出后采购触发、报表统计（决策 13 流量维度一期不做，库存统计后续定）

## 3. 图片归属规则（用户 2026-09-03 拍板，极其重要）

### 3.1 核心规则：1 个 SKU + 1 个店铺 = 1 套图

- ✅ **一套图 = 一个（SKU × 店铺）**：同一个商品（SKU）在不同店铺出售，**各用各的图**——因为不同店铺可能有不同风格/定位/定价，图要差异化
- ✅ **一个 SKU 跨 N 个店铺 = N 套图**（图集的归属键是 (SKU, 店铺)，不是 SKU 本身）
- ✅ 同一套图内可以有**多张图**（主图/轮播/详情/多角度），都属于同一 (SKU, 店铺)
- ❌ **一套图不得同时属于两个店铺**

### 3.2 店铺是通用实体（用户 2026-09-03 拍板）

- **店铺 = 任何平台的店铺，本质上没有区别**：Etsy A 店 / Etsy B 店 / 闲鱼店 / 小红书店 / 未来新平台店——都是同一个"店铺"实体，只是平台字段不同
- **将来平台必然拓展**，数据结构必须天然支持（店铺表 + 平台字段，不针对某平台特化）
- 上架、图集、SEO 全部按店铺维度组织

### 3.3 图片来源标记 + 视频留位（用户 2026-09-03 确认）

- **每张图必须带来源标记**（防侵权可追溯）：`扒图（附原链接）/ 自拍 / AI 生成 / 授权图`
- 扒图商用有侵权风险，来源标记让每张图可追溯（将来被投诉/删链接时能查）
- **视频留位**：SKU 可关联视频（Etsy 支持商品视频），一期不做，数据结构留位置（媒体挂 SKU 下）

### 3.4 一图一主体（多主体图处理）

一张图里有多个主体（如打火机 + 烟），且两者要**分别售卖**时：

- 这张图**不能共用**——必须先处理成"一图一主体"：
  - **裁剪**：裁成打火机一张、烟一张，各自对应自己的 SKU/卖法
  - **补拍/生成**：给打火机单独一张、烟单独一张
- 处理动作归属：图片处理环节（COMFYUI）或建档时人工处理（待定，见 §7 开放项）

### 3.5 组合卖法的图

- 卖套餐（打火机+烟），**必然有一张"打火机+烟"的套餐图**——它属于"套餐卖法 × 店铺"（同 SKU 规则：每个店铺各一套套餐图）
- 套餐图来源：
  1. **拼图**：把打火机图和烟图拼成一张（COMFYUI 可做）
  2. **专门拍/生成**：拍一张打火机+烟在一起的图（或 AI 生成）

### 3.6 上架必须引用系统内已建档的 SKU（用户 2026-09-03 拍板）

- **系统里没有的 SKU，禁止在 Etsy（及任何店铺）上架**
- 上架 Listing 必须引用系统内已有 SKU 档案（含图、名称、规格、成本）
- 与三工作台 v3 铁律③一致：「Etsy 变体 SKU 框填本地 SKU（订单自动对上的钥匙）」——订单回来时平台 SKU 直接对上系统内本地 SKU

### 3.7 SKU 粒度与虚拟 SKU（2026-09-03 调研定案：Etsy 机制实证）

**属性变体（颜色/尺寸）→ 每变体组合一个物料 SKU**（调研结论，见 `docs/调研-Etsy变体与SKU机制.md`）：

- Etsy 机制：每个变体组合（如 银色打火机 / 黑色打火机）= API 一个 product = **一个 SKU 框 + 独立价格/数量**；最多 3 个变体维度
- **物料层按「颜色 × 尺寸」组合粒度建 SKU**（SKU-打火机-银色 / SKU-打火机-黑色），**不做"一个 SKU 带属性"**
- 理由：平台 SKU 粒度 = 变体组合；一个 SKU 带属性则订单回来无法区分颜色 → 接单采购/扣库存失效
- Etsy 变体 SKU 框**直接填本地物料 SKU，零映射**
- **库存按变体组合 SKU 独立记录**（用户 2026-09-03 确认）：金色打火机一个库存、银色打火机一个库存（再叠仓库维度 = SKU × 仓库），各自独立扣减/采购/报损；因金色/银色成本、采购来源可能不同，互不掺和
- 可选：同款不同色归一个「款式/商品组」概念（管理视图用，不改变 SKU 粒度）

**SKU 编号原则（用户 2026-09-03 拍板：目的 = 满足 Etsy 变体要求即可）**：

- **不预先设计编码规则**（商品种类/规格维度太多，规则定死反而束缚）
- 编号 = 建档时人工填写，**自由起名**（DHJ-1 / LTR-GOLD / 随用随长）
- 系统只做两件事：**格式校验**（禁逗号/斜杠等 Etsy 非法符号）+ **查重**（全店唯一）
- 商品/颜色/尺寸 = **结构化字段**（管查询/统计/管理），编号不参与逻辑判断
- 系统可选自动建议编号（按商品名首字母+序号），可接受可改——规则是"建议 + 人说了算"，非强制

**套餐（组合卖法）→ 卖法层登记"卖法平台 SKU（虚拟 SKU）"**：

- 套餐作为独立 Listing 上架时，Etsy SKU 框填**组合虚拟 SKU**（如 `COMBO-LIGHTER-CIG`）
- 虚拟 SKU 登记在**卖法层**，**全局唯一**（前缀区分实物 SKU，如 COMBO-），映射 BOM（引用哪些物料 SKU 各 ×N）
- **不污染物料层**（物料层只有实物 SKU）；**禁止在 SKU 框填两个 SKU**（一个框一个值 + 官方禁逗号/斜杠）
- Etsy 官方 "Buy Together" 捆绑是促销工具（链接 ≤3 个 Listing 同购、各带原 SKU），**不是套餐 Listing**——套餐 = 独立 Listing + 虚拟 SKU

**订单对库存两段式**：

- 订单 SKU 命中**实物物料 SKU** → 直接扣该 SKU 库存（BOM 单件）
- 订单 SKU 命中**虚拟 SKU（COMBO- 前缀）** → 按卖法 BOM 展开 → 物料层各扣对应数量

### 3.8 对应关系总结

```
① 实物层：打火机-银色 ×100、打火机-黑色 ×50、烟 ×100   ← 库存只记这里，按 SKU×仓库
② 物料层：SKU-打火机-银色、SKU-打火机-黑色、SKU-烟    ← 变体组合粒度，全局档案一份
③ 店铺层：店铺A / 店铺B / 闲鱼店 / …（通用实体）
④ 图集层：一套图 = (SKU × 店铺)
     SKU-打火机-银色 × 店铺A → 店铺A的银色打火机图集
     SKU-打火机-黑色 × 店铺A → 店铺A的黑色打火机图集
     SKU-烟 × 店铺A          → 店铺A的烟图集
     套餐(打火机+烟) × 店铺A → 店铺A的套餐图集
⑤ 卖法层：单卖打火机-银色 / 单卖烟 / 套餐(打火机+烟)   ← SEO、上架在店铺×卖法维度
     · 卖法平台 SKU（虚拟 SKU）：套餐 = COMBO-LIGHTER-CIG（BOM 映射物料）
     · 单卖 = 直接引用物料 SKU
```

## 4. 素材采集规则（用户 2026-09-03 拍板）

- **素材两个来源**：
  1. **扒图**：填链接（小红书/闲鱼）→ 图 + 标题/标签/作者（一个链接 = 一组，天然成组）
  2. **相机拍摄**：自己拍的实拍图（一次拍摄 = 一组）
- **处理两路**：
  - 大部分 → **COMFYUI 处理**（换背景/去水印/修图/生成）
  - 一部分 → **不经过 COMFYUI**，直接用原图（拍得够好/图够干净）
- 两路最终汇合为**可用的商品图**，进入物料/卖法层挂靠

## 5. 卖法自由组合规则（用户 2026-09-03 拍板）

- 每个卖法 = 一个可售单元，**自由组合**：
  - 单卖 A / 单卖 B / 套餐 A+B / 套餐 A+B+C…
- 套餐可**嵌套叠加**（打火机+烟 是套餐，打火机+烟+火柴 是另一个套餐）——都是配方逻辑，不会更复杂
- **每个卖法都要做 SEO**（A 一套、B 一套、A+B 套餐一套——套餐的 SEO 突出套餐价值）

> 对五层模型做压力测试时发现的 12 个边界场景，用户逐条确认如下：

| # | 场景 | 结论 | 说明 |
|---|---|---|---|

| 5 | 商品生命周期 | **需要** | SKU 有状态：建档中→在售→下架/停产；下架保留档案供历史订单追溯（§2.5 补充） |

| 8 | 定制/限量商品 | **待定** | 有这种情况（如 CRM 定制花束），无固定 SKU/库存为 0/接单生产，未想好（§8 开放项） |
| 9 | 多仓库 | **需要** | 目前有代发仓 + 自有仓；库存按「SKU × 仓库」记录（§2.3） |
| 10 | 视频 | **暂不做，留位** | 视频可关联在 SKU 下，一期不做（§3.3 补充） |
| 11 | 广告/社媒图 | **待定** | Listing 图 vs 广告/社媒图是否区分用途未想好（§8 开放项） |
| 12 | 同店同 SKU 双 Listing | **不确认** | 暂不确定是否有 A/B 测试场景，记录备查（§8 开放项） |

### 已确认补充规则（并入对应章节）

- **图片来源标记**（§3.3）：每张图必须记录来源（扒图/自拍/AI 生成/授权），防侵权可追溯
- **SKU 生命周期**：状态（建档中/在售/下架/停产），下架保留档案
- **定价归属**：定价挂「店铺 × 卖法」，与 SKU 无关
- **视频留位**：SKU 可关联视频（一期不做，数据结构留位置）

## 6. 对后续系统的约束（SEO / ERP 必须遵守）

### 6.1 SEO 优化（v0.5 及后续）

- SEO 的对象是**卖法（可售单元）**，不是物料、不是实物
- 每个卖法独立出「标题/描述/标签」（套餐卖法有自己的 SEO 初稿，突出套餐价值）
- 与三工作台 v3 建档环节衔接：选品卡建档时「标题/描述」= 刘全 seo_optimize 出初稿（输入：卖法对应图 + 目标关键词）→ 提案进 TM → 人改后用于上架
- **定价归属**（用户 2026-09-03 确认）：定价**不关联 SKU**，挂在「店铺 × 卖法」上（同套餐不同店可不同价）；定价建议 v0.6 接 ERP 数据后做，数据结构留位置

### 6.2 ERP 对接（v0.6 及后续）

- 刘全对 ERP：卖法（可售单元）图包/SEO 初稿/选品建议 → 选品卡；上架任务单
- ERP 对刘全：只读 v_* 视图（订单/库存/成本/采购）
- **SKU 建档 = 单独大规划**（用户拍板，本文件只定分层模型与"图挂 SKU×店铺"的规则，建档流程细节另立规划）

## 8. 讨论记录（2026-09-03，与用户逐点确认）

1. 素材两来源（扒图 + 相机拍摄）→ 两路处理（COMFYUI / 直接用）→ 汇合可用商品图 ✅
2. 一张图可有多主体（打火机+烟），要分别售卖 → **一图一卖法规则**（多角度除外），多主体先拆/补 ✅
3. 卖套餐的库存怎么存 → **分开存（打火机 1、烟 1）+ 套餐按 BOM 配方扣减**，套餐不占独立库存 ✅
4. 商品图和实物怎么对应 → **一套图 = 1 个 SKU × 1 个店铺**（图不挂实物、不单挂 SKU；跨店各用各的图）；套餐图属于"套餐卖法 × 店铺" ✅
5. 本规则为整个刘全数据底层逻辑，后续 SEO/ERP 必须基于此 ✅
6. 查漏补缺 12 场景（§5.5）：库存接单采购模式（绝大多数不备货、部分备货）✅ / 多仓库（代发仓+自有仓）✅ / 库存流水 ✅ / 图片来源标记 ✅ / SKU 生命周期 ✅ / 定价不关联 SKU ✅ / 视频留位 ✅；属性变体、Etsy 变体框填写、定制商品、广告图、双 Listing = 待定（§7）
7. 属性变体 + Etsy 变体框填写 → **调研定案（§3.7）**：每变体组合一个物料 SKU；套餐填组合虚拟 SKU（COMBO- 前缀）登记卖法层映射 BOM；订单对库存两段式（实物 SKU 直接扣 / 虚拟 SKU 按 BOM 展开扣）；开放项 5/6 关闭（详见 `docs/调研-Etsy变体与SKU机制.md`）
8. SKU 编号 → **用户拍板：目的 = 满足 Etsy 变体要求即可**——不预先定编码规则，自由编号 + 系统格式校验/查重，规格用结构化字段管（§3.7）
