> **状态：已确认（2026-09-03 与用户逐点讨论拍板）** ｜ 优先级：**最高**——这是整个刘全系统数据的底层地基
> 后续 SEO 优化、ERP 对接、SKU 建档等一切设计**必须基于本规则**（引用本文件，不得另立模型）
> 配套交互白板：`docs/diagrams/白板-业务全流程.html`（讨论中逐步绘制，本文件是其文字版定稿）

## 0. 一句话

**实物（仓库里的货）≠ 物料（SKU 档案）≠ 店铺（通用实体：Etsy 店/闲鱼店/未来平台）≠ 卖法（可售单元/Listing）**，分层各管各的；
**一套图 = 1 个 SKU × 1 个店铺**（图不挂在 SKU 上，挂在"SKU × 店铺"上）；**库存记在实物/物料上，不分店**；**组合卖法 = 配方表（BOM），不占独立库存**；**系统里没有的 SKU 禁止上架**。

## 1. 分层模型（核心）

```
┌─────────────────────────────────────────────────────────────┐
│ ⑤ 卖法层（可售单元 / Listing）      ← SEO、上架在 店铺×卖法 维度 │
│    单卖打火机 / 单卖烟 / 套餐(打火机+烟) / 套餐(+火柴)…          │
│    · 组合卖法 = 配方表（BOM）：引用下面物料，各 ×N               │
├─────────────────────────────────────────────────────────────┤
│ ④ 图集层                         ← 一套图 = (SKU × 店铺)       │
│    SKU-打火机×店铺A → A的打火机图集 ｜ SKU-打火机×店铺B → B的图集 │
│    · 主图/轮播/详情/多角度都属于同一套图                        │
├─────────────────────────────────────────────────────────────┤
│ ③ 店铺层（通用实体）              ← 不分平台，结构相同            │
│    店铺A(Etsy) / 店铺B(Etsy) / 闲鱼店 / 小红书店 / 未来平台店    │
├─────────────────────────────────────────────────────────────┤
│ ② 物料层（SKU 档案，全局唯一）     ← 名称/规格/成本不分店          │
│    打火机 SKU / 烟 SKU / …                                     │
├─────────────────────────────────────────────────────────────┤
│ ① 实物层（仓库库存）              ← 库存数量只记这一层，不分店     │
│    打火机 ×100 / 烟 ×100 / …                                   │
└─────────────────────────────────────────────────────────────┘
```

### 各层职责（明确分工，不越界）

| 层 | 管什么 | 不管什么 |
|---|---|---|
| ① 实物层 | 库存数量、实物 | 图、SEO、卖法、店铺 |
| ② 物料层 | SKU 档案（名称/规格/成本，全局一份） | 库存、组合、上架、店铺差异 |
| ③ 店铺层 | 店铺实体（平台字段 + 店铺维度组织） | 库存、物料内容 |
| ④ 图集层 | 每套图（= SKU × 店铺） | 库存、SEO |
| ⑤ 卖法层 | 卖法的 SEO、上架内容（店铺 × 卖法维度） | 库存、实物 |

## 2. 库存规则（用户 2026-09-03 拍板）

- **库存分开存**：仓库里有什么就存什么——打火机 100、烟 100，**每样一行**
- **组合卖法不占库存**：套餐（打火机+烟）**不是仓库里的一件货**，不单独记库存
- **卖套餐 = 按配方扣减**：卖 1 个套餐 → 打火机 -1、烟 -1（BOM 展开），仓库账始终只有实物那几行
- **为什么必须这样**：
  1. 符合仓库实物（不存在"套餐"这堆货）
  2. 组合会爆炸（5 个单品任意组合 = 2⁵=32 种卖法，组合建库存会失控）——分开存，组合随便加，库存零变化
  3. 与三工作台 v3 铁律一致：「物料 = 仓库里一件货，不裂物料」

## 3. 图片归属规则（用户 2026-09-03 拍板，极其重要）

### 3.1 核心规则：1 个 SKU + 1 个店铺 = 1 套图

- ✅ **一套图 = 一个（SKU × 店铺）**：同一个商品（SKU）在不同店铺出售，**各用各的图**——因为不同店铺可能有不同风格/定位/定价，图要差异化
- ✅ **一个 SKU 跨 N 个店铺 = N 套图**（图集的归属键是 (SKU, 店铺)，不是 SKU 本身）
- ✅ 同一套图内可以有**多张图**（主图/轮播/详情/多角度），都属于同一 (SKU, 店铺)
- ❌ **一套图不得同时属于两个店铺**

### 3.2 店铺是通用实体（用户 2026-09-03 拍板）

- **店铺 = 任何平台的店铺，本质上没有区别**：Etsy A 店 / Etsy B 店 / 闲鱼店 / 小红书店 / 未来新平台店——都是同一个"店铺"实体，只是平台字段不同
- **将来平台必然拓展**，数据结构必须天然支持（店铺表 + 平台字段，不针对某平台特化）
- 上架、图集、SEO 全部按店铺维度组织

### 3.3 一图一主体（多主体图处理）

一张图里有多个主体（如打火机 + 烟），且两者要**分别售卖**时：

- 这张图**不能共用**——必须先处理成"一图一主体"：
  - **裁剪**：裁成打火机一张、烟一张，各自对应自己的 SKU/卖法
  - **补拍/生成**：给打火机单独一张、烟单独一张
- 处理动作归属：图片处理环节（COMFYUI）或建档时人工处理（待定，见 §7 开放项）

### 3.4 组合卖法的图

- 卖套餐（打火机+烟），**必然有一张"打火机+烟"的套餐图**——它属于"套餐卖法 × 店铺"（同 SKU 规则：每个店铺各一套套餐图）
- 套餐图来源：
  1. **拼图**：把打火机图和烟图拼成一张（COMFYUI 可做）
  2. **专门拍/生成**：拍一张打火机+烟在一起的图（或 AI 生成）

### 3.5 上架必须引用系统内已建档的 SKU（用户 2026-09-03 拍板）

- **系统里没有的 SKU，禁止在 Etsy（及任何店铺）上架**
- 上架 Listing 必须引用系统内已有 SKU 档案（含图、名称、规格、成本）
- 与三工作台 v3 铁律③一致：「Etsy 变体 SKU 框填本地 SKU（订单自动对上的钥匙）」——订单回来时平台 SKU 直接对上系统内本地 SKU

### 3.6 对应关系总结

```
① 实物层：打火机 ×100、烟 ×100                ← 库存只记这里，不分店
② 物料层：SKU-打火机、SKU-烟（全局档案一份）    ← 名称/规格/成本不分店
③ 店铺层：店铺A / 店铺B / 闲鱼店 / …（通用实体）
④ 图集层：一套图 = (SKU × 店铺)
     SKU-打火机 × 店铺A → 店铺A的打火机图集
     SKU-打火机 × 店铺B → 店铺B的打火机图集
     SKU-烟 × 店铺A     → 店铺A的烟图集
     套餐(打火机+烟) × 店铺A → 店铺A的套餐图集
⑤ 卖法层：单卖打火机 / 单卖烟 / 套餐(打火机+烟)  ← SEO、上架在店铺×卖法维度组织
```

## 4. 素材采集规则（用户 2026-09-03 拍板）

- **素材两个来源**：
  1. **扒图**：填链接（小红书/闲鱼）→ 图 + 标题/标签/作者（一个链接 = 一组，天然成组）
  2. **相机拍摄**：自己拍的实拍图（一次拍摄 = 一组）
- **处理两路**：
  - 大部分 → **COMFYUI 处理**（换背景/去水印/修图/生成）
  - 一部分 → **不经过 COMFYUI**，直接用原图（拍得够好/图够干净）
- 两路最终汇合为**可用的商品图**，进入物料/卖法层挂靠

---

## 5. 卖法自由组合规则（用户 2026-09-03 拍板）

- 每个卖法 = 一个可售单元，**自由组合**：
  - 单卖 A / 单卖 B / 套餐 A+B / 套餐 A+B+C…
- 套餐可**嵌套叠加**（打火机+烟 是套餐，打火机+烟+火柴 是另一个套餐）——都是配方逻辑，不会更复杂
- **每个卖法都要做 SEO**（A 一套、B 一套、A+B 套餐一套——套餐的 SEO 突出套餐价值）

## 6. 对后续系统的约束（SEO / ERP 必须遵守）

### 6.1 SEO 优化（v0.5 及后续）

- SEO 的对象是**卖法（可售单元）**，不是物料、不是实物
- 每个卖法独立出「标题/描述/标签」（套餐卖法有自己的 SEO 初稿，突出套餐价值）
- 与三工作台 v3 建档环节衔接：选品卡建档时「标题/描述」= 刘全 seo_optimize 出初稿（输入：卖法对应图 + 目标关键词）→ 提案进 TM → 人改后用于上架

### 6.2 ERP 对接（v0.6 及后续）

- 刘全对 ERP：卖法（可售单元）图包/SEO 初稿/选品建议 → 选品卡；上架任务单
- ERP 对刘全：只读 v_* 视图（订单/库存/成本/采购）
- **SKU 建档 = 单独大规划**（用户拍板，本文件只定分层模型与"图挂 SKU×店铺"的规则，建档流程细节另立规划）

## 8. 讨论记录（2026-09-03，与用户逐点确认）

1. 素材两来源（扒图 + 相机拍摄）→ 两路处理（COMFYUI / 直接用）→ 汇合可用商品图 ✅
2. 一张图可有多主体（打火机+烟），要分别售卖 → **一图一卖法规则**（多角度除外），多主体先拆/补 ✅
3. 卖套餐的库存怎么存 → **分开存（打火机 1、烟 1）+ 套餐按 BOM 配方扣减**，套餐不占独立库存 ✅
4. 商品图和实物怎么对应 → **一套图 = 1 个 SKU × 1 个店铺**（图不挂实物、不单挂 SKU；跨店各用各的图）；套餐图属于"套餐卖法 × 店铺" ✅
5. 本规则为整个刘全数据底层逻辑，后续 SEO/ERP 必须基于此 ✅
