# 刘全版本规划

> 版本号 = 系统能力里程碑，标记"刘全能做什么"的跃迁。
> 本文档不做待办堆叠（待办进详设与变更日志），只维护版本里程碑。

## 版本号三条规矩

1. 发版必须 git 落地（tag + commit），否则不算发版
2. 业务工序增量（新工序/工序改造）不绑版本号，只进变更日志，做完即用
3. 一版验收标准全达成并验证 = 可发版；未达不发，不允许"部分完成的版本"

## 各版本定义

### v0.1 引擎地基

**目标**：引擎最小内核命令行跑通一个工序，全程可审计。

**范围**：5 相位状态机、PydanticAI 接入（DeepSeek）、工序注册表（YAML + 拒载）、审计落库、检查点。一个演示工序。

**验收**：
- 命令行提交工序任务 -> 状态机全相位走完 -> DONE
- 注册表缺字段拒载（反向测试覆盖）
- 审计可查输入/输出/token/耗时
- 中途 kill，重启后从检查点续跑

### v0.2 TM + 引擎接通

**目标**：AI 建议自动变任务，人工处理完回流。

**范围**：PG16 双 database（业务库 + 引擎库）、任务队列（SKIP LOCKED）、TM 数据模型、TaskProposal 审核流（无优先级分级，决策 11 修订）、FastAPI 骨架 + 共享密码登录（三角色）+ 工作台占位（决策 15）。**任务生成双通道 + 审核依据强制 + 禁幻觉（决策 16）与任务生命周期（决策 17，2026-08-28 并入详设 v0.2）。**

**验收**（2026-08-28 全部达成，A12-A26 断言全绿）：
- [x] 触发工序链 -> 产出提案 -> 全部进审核页 -> 人工批准后成任务
- [x] 人工处理 -> 状态回流引擎可见（task_event 流水 + 追溯闭环）
- [x] 引擎三接口（建任务/查任务/查注册表）可用
- [x] 禁幻觉三件套（机器校验拒落）+ 必填回复 + 派生 + 防重 + 逾期提醒 + 编辑（决策 16/17）

### v0.3 CRM 平移

**目标**：EOMS 已验证的 CRM 链路在刘全跑通，体验不倒退。

**范围**：翻译/快照/回复/待办四工序平移（调用层换 PydanticAI）、CRM 页面、~~EOMS SQLite 数据迁移~~（决策 20 取消）、飞书通知、任务标签 + 流转机制、业务写入接口化（决策 26）。复核反馈 #6 增：任务步骤（轻量子任务，task_step 表 + 完成守卫）。

**验收**（2026-08-30 全部达成，A27-A37 断言全绿 + 复核反馈 #1-#6 处理）：
- [x] 粘贴对话 -> 翻译+快照+待办自动跑完，端到端 <= 6s（实测 ≈4.3s，EOMS 基线 5.8s）
- [x] 待办出现在 TM 清单（标来源 CRM；source.customer_id 关联客户）
- [x] 存量数据不迁移（决策 20），从零录数据
- [x] 广成电脑关机不影响（链路全程云上）
- [x] 复核反馈 #1-#6：任务清单固定高度+滚动 / 完成作废去编辑 / 按钮统一 btn-sm / 派生 422 修复 / 任务步骤 / 派生弱化（link_parent 默认关）+ 逾期筛选布局修复

### v0.4 定时闭环（系统自己动起来）

**目标**：系统第一次不需要人触发自己干活——定时自动检查、任务自动就位 TM。

**范围**（决策 33 收敛，2026-08-30 用户拍板）：
- **定时触发底座**（引擎）：schedule 表（定时链清单 + 上次/下次运行）+ 调度器 + 去重（同一业务对象 N 分钟/当天不重复触发）。事件触发/配额记账**不做**（用不到就不做，留底座扩展位）
- **设置 → 定时任务页**（导航新增「设置」，v0.4 只做定时一项）：定时链清单页面化——哪些链跑/几点跑/开关/上次下次运行时间
- **首批定时链 1 条**：CRM 客户超 N 天未跟进提醒（每天自动跑 → 提醒任务进 TM；N 从 settings 表读，顺手把 `FOLLOW_UP_DAYS=5` 硬编码去硬编码）
- **settings 表立地基**：键值对配置表（v0.4 存定时任务清单 + 跟进天数；店铺/AI/通知/权限往同一张表加键加页面，决策 33 设置页完整清单）
- SEO/扒图/ERP/权限：**全部延后，不进 v0.4**

**验收**：
- 定时任务每天自动跑，提醒任务就位在 TM（早上打开看到"该跟进谁"）
- 同一客户当天重复触发只生成一次（去重测试覆盖）
- 设置页可配置定时链清单（开关/时间）并生效；跟进天数改设置页生效
- 调度器崩溃重启后不漏跑/不重跑（幂等，复用检查点机制）
- 四绿全绿 + 验收断言全绿

**验收**：

- SEO 体检发现排名下滑 -> 优化建议任务出现在 TM

### v0.7 设置与权限（决策 30 + 决策 33 完整清单）

**目标**：刘全可配置——店铺 / AI / 通知 / 权限集中管理。

**说明**：定时任务管理已提前进 v0.4（决策 33，导航「设置」v0.4 只做定时一项）；本版本补齐设置页其余内容。

**范围**（设置页完整清单，决策 33）：
- **① 店铺管理**：店铺清单（名称/备注/启用停用），CRM source_shop 下拉候选
- **② AI 配置**：API 密钥页面化（DeepSeek key，现 .env）、模型选择（models.yaml 页面化）、风格指南/术语表（工序 config 页面化）
- **③ 通知配置**：飞书 webhook 页面化（决策 21 留账，现 .env）、通知开关
- **⑤ 权限系统**：用户/角色管理、行级权限（决策 17 第 2 条：同页面不同人看到不同任务数量与内容，精确到人和数据）、登录改造（三角色标签 → 真实用户）
- **⑥ 系统参数**：逾期天数等去硬编码（settings 表，v0.4 已起头：FOLLOW_UP_DAYS）

**验收**：设置页可配置上述项并生效；权限系统上线（用户登录/角色分配/行级可见性）；v1.0 一期发版前权限到位。
