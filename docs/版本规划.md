## 版本号三条规矩

1. 发版必须 git 落地（tag + commit），否则不算发版
2. 业务工序增量（新工序/工序改造）不绑版本号，只进变更日志，做完即用
3. 一版验收标准全达成并验证 = 可发版；未达不发，不允许"部分完成的版本"

## 版本主线（2026-09-03 重做说明）

**重做原因**：数据底层逻辑（五层模型：实物/物料/店铺/图集/卖法）定稿后，版本按旧"系统模块"切会产生反复返工（每版都碰底层逻辑一角）；v0.5 扒图"几乎不能用"的根因之一就是无地基开发。新主线按五层模型**自底向上**推进：

```
已发版：v0.1 引擎 → v0.2 TM → v0.3 CRM → v0.4 设置+定时 ✅
─────────────────────────────────────────────────
v0.5  SEO + CRM 图片（已开发，数据层：SEO 域）
v0.6  扒图重做 = 素材库（图集层雏形：链接记录 + 图挂 SKU×店铺）
v0.7  SKU 建档（物料层：SKU 管理/变体/图集/定制 CUSTOM）
v0.8  卖法组合 + SEO 建档联动（卖法层：单卖/套餐 + 每卖法 SEO 初稿）
v0.9  上架 + ERP 对接（卖法上架 + NocoBase 只读 + 定价建议）
v1.0  权限 + 一期收口
```

**关键调整**：原 v0.6 ERP 顺延（ERP 要等物料/SKU/卖法有数据才能对接）；SKU 建档提前（图挂 SKU、SKU 是中间承重层）；权限仍留最后（决策 34）。
