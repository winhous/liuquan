# 刘全版本规划

> 版本号 = 系统能力里程碑，标记"刘全能做什么"的跃迁。
> 本文档不做待办堆叠（待办进详设与变更日志），只维护版本里程碑。

## 版本号三条规矩

1. 发版必须 git 落地（tag + commit），否则不算发版
2. 业务工序增量（新工序/工序改造）不绑版本号，只进变更日志，做完即用
3. 一版验收标准全达成并验证 = 可发版；未达不发，不允许"部分完成的版本"

## 各版本定义

### v0.1 引擎地基

**目标**：引擎最小内核命令行跑通一个工序，全程可审计。

**范围**：5 相位状态机、PydanticAI 接入（DeepSeek）、工序注册表（YAML + 拒载）、审计落库、检查点。一个演示工序。

**验收**：
- 命令行提交工序任务 -> 状态机全相位走完 -> DONE
- 注册表缺字段拒载（反向测试覆盖）
- 审计可查输入/输出/token/耗时
- 中途 kill，重启后从检查点续跑

### v0.2 TM + 引擎接通

**目标**：AI 建议自动变任务，人工处理完回流。

**范围**：PG16 双 database（业务库 + 引擎库）、任务队列（SKIP LOCKED）、TM 数据模型、TaskProposal 审核流（无优先级分级，决策 11 修订）、FastAPI 骨架 + 共享密码登录（三角色）+ 工作台占位（决策 15）。

**验收**：
- 触发工序链 -> 产出提案 -> 全部进审核页 -> 人工批准后成任务
- 人工处理 -> 状态回流引擎可见
- 引擎三接口（建任务/查任务/查注册表）可用

### v0.3 CRM 平移

**目标**：EOMS 已验证的 CRM 链路在刘全跑通，体验不倒退。

**范围**：翻译/快照/回复/待办四工序平移（调用层换 PydanticAI）、CRM 页面、EOMS SQLite 数据迁移、飞书通知。

**验收**：
- 粘贴对话 -> 翻译+快照+待办自动跑完，端到端 <= 6s（EOMS 基线 5.8s）
- 待办出现在 TM 清单（标来源）
- 存量数据完整迁入
- 广成电脑关机不影响

### v0.4 调度完整版

**目标**：无人工干预，系统自己发现事、生成任务。

**范围**：事件触发 + 定时触发 + 去重限流 + 外部配额记账（eHunt 200 条/天）。

**验收**：
- 定时任务每天自动跑，任务就位在 TM
- 重复事件被去重
- 配额超限时工序排队而非报错

### v0.5 SEO + 扒图

**目标**：SEO 工具与选品扒图进刘全。

**范围**：keyword-research / seo-optimize 平移 + eHunt 双通道、listing 体检定时链、image-download 平移、新链（扒图 -> 图片体检 -> 选品建议 -> TM 任务）。

**验收**：
- 丢链接进扒图，选品任务出现在 TM
- SEO 体检发现排名下滑 -> 优化建议任务出现在 TM
- eHunt 配额进引擎记账

### v0.6 ERP 增强

**目标**：库存与订单事实进刘全视角。

**范围**：读 NocoBase 25 个 v_* 视图（只读）、补货建议/缺口分析/异常预警工序，产出任务进 TM。

**验收**：
- 库存体检发现低库存 -> 补货任务进 TM（带销量/库存/交期上下文）
- 全程对 NocoBase 零写入

### v1.0 一期发版

**目标**：总验收画面达成，EOMS 退役。

**范围**：v0.1-v0.6 收口 + 管理页（任务暂停/重跑/回放、审计查询）+ EOMS 下线 + 打 tag。

**验收**（概设 6.2 总验收画面）：
1. 每天打开刘全 Web，看到跨域任务清单（标来源；逾期标红，无优先级分级——决策 11 修订）
2. 粘贴对话全链路自动跑完
3. 每天早库存体检 + SEO 体检任务自动就位
4. 人工处理 -> 结果回流 -> 引擎判断下一步
5. 管理页可查每次 AI 调用，任务可暂停/重跑/回放
6. 广成电脑关机，刘全一切正常
