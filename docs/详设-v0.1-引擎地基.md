# 1. 范围

v0.1 交付一个**可独立运行、可审计、可恢复**的引擎最小内核：

```text
命令行触发 -> 建任务入队 -> 状态机逐相位执行 -> 审计落库 -> 检查点可恢复
```

明确不包含（后续版本）：常驻 runner 进程与 web（v0.2）、事件/定时触发（v0.4）、配额记账（v0.4）、真实业务工序（v0.3/v0.5/v0.6）。v0.1 的两个工序（demo-echo + 翻译雏形）只为验证内核，不追求业务完整。

# 2. 状态机详设

## 2.1 相位职责

| 相位 | 职责 | 谁干活 | 失败语义 |
|---|---|---|---|
| INIT | Policy 校验：域权限 / 输入类型 / 风险级；装配上下文 | 代码 | 校验不过 = FAILED（不可重试，输入有问题） |
| REASON | 调 LLM，产出结构化输出 | **AI（唯一出现点）** | 类型不过自动 re-ask；耗尽 = FAILED |
| ACT | 执行副作用（写库 / 产出提案） | 代码 | 失败可重试（幂等要求见 §2.4） |
| OBSERVE | 读回副作用结果 | 代码 | 读不回 = FAILED（写了个寂寞） |
| VERIFY | 业务断言（代码写死） | 代码 | 断言不过 = FAILED（宁失败不假成功） |
| DONE / FAILED / PAUSED | 终态（PAUSED 非终态，可恢复） | -- | -- |

## 2.2 相位转换表（全部代码写死，AI 无权决定下一步）

| 当前 | 条件 | 下一 | 转换前动作 |
|---|---|---|---|
| INIT | Policy 全绿 | REASON | 落检查点 |
| INIT | 校验不过 | FAILED | 记 error |
| REASON | 输出过类型校验 | ACT | 落检查点（含 LLM 结果） |
| REASON | 校验失败且 re-ask < 上限 | REASON | 记审计（result=reask） |
| REASON | re-ask 耗尽 / LLM 异常且重试耗尽 | FAILED | 记 error |
| ACT | 副作用成功 | OBSERVE | 落检查点 |
| ACT | 副作用失败且 attempt < 上限 | ACT | 退避后重试本相位 |
| ACT | 重试耗尽 | FAILED | 记 error |
| OBSERVE | 读回成功 | VERIFY | 落检查点 |
| VERIFY | 断言全绿 | DONE | 落终态检查点 |
| VERIFY | 任一断言红 | FAILED | 记 error（含断言名） |
| 任意运行相位 | 人工 pause 指令 | PAUSED | 落检查点（含内存状态） |
| PAUSED | 人工 resume | 恢复到检查点记录的相位 | 从检查点 state 重建内存 |

不存在 VERIFY -> REASON 的回路（v0.1 不做自动返工；人工 resume 重跑整工序）。

## 2.3 崩溃恢复

- 每次相位转换**前**写 `engine_checkpoint`（含：step 定位 + 当前相位 + 相位已产出结果 + 续跑所需内存状态 JSON）
- 进程崩溃重启 -> `resume <task_id>`：取该任务最后一条 checkpoint，从其记录的相位继续
- 关键保证：**REASON 已成功的 LLM 结果在 checkpoint 里，续跑不重烧 token**（验收断言）
- PAUSED 与崩溃恢复走同一条路径（人工暂停 = 主动制造一次"优雅崩溃"）

## 2.4 幂等要求

ACT 重试的前提是副作用幂等。约定（技术定）：v0.1 工序副作用一律「先算好完整数据、一次写入、带唯一键」，重试 = upsert。不满足幂等的副作用不允许声明 `risk: write`（loader 校验提示，v0.1 仅提示不强制）。

# 3. 引擎库表结构（database: liuquan_engine）

v0.1 建 4 张表（配额/调度表属 v0.4，不提前建）。

```sql
-- 引擎任务：一次触发 = 一条，一条 = 一条链的完整执行
CREATE TABLE engine_task (
    id            BIGSERIAL PRIMARY KEY,            -- 展示形式 e-<6位零填充>
    chain_id      TEXT NOT NULL,                    -- 引用链注册表（chat-inbox 等）
    status        TEXT NOT NULL DEFAULT 'queued',   -- queued/running/paused/done/failed/cancelled
    trigger_type  TEXT NOT NULL,                    -- manual/event/schedule（v0.1 只有 manual）
    trigger_ref   TEXT,                             -- manual=操作者标识；event/schedule=来源 id
    input         JSONB NOT NULL,                   -- 链入参（INIT 时过链声明的 input Model）
    current_step  INT NOT NULL DEFAULT 0,           -- 当前工序序号（0 起）
    current_step_row BIGINT,                        -- 当前 engine_step.id（恢复定位用）
    error         TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    started_at    TIMESTAMPTZ,
    finished_at   TIMESTAMPTZ
);
CREATE INDEX idx_task_status ON engine_task(status) WHERE status IN ('queued','running','paused');

-- 工序实例：每个工序每次执行一条（重试 = 新行，attempt+1）
CREATE TABLE engine_step (
    id            BIGSERIAL PRIMARY KEY,
    task_id       BIGINT NOT NULL REFERENCES engine_task(id),
    step_index    INT NOT NULL,                     -- 链内序号（0 起，与 current_step 对应）
    worker_id     TEXT NOT NULL,                    -- 引用工序注册表
    phase         TEXT NOT NULL DEFAULT 'INIT',     -- 当前相位（终态时停在最后相位）
    status        TEXT NOT NULL DEFAULT 'running',  -- running/done/failed/paused
    input         JSONB NOT NULL,                   -- 本工序入参（过工序 input Model）
    output        JSONB,                            -- VERIFY 通过后写入
    attempt       INT NOT NULL DEFAULT 0,           -- 0 起第几次重试
    error         TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    started_at    TIMESTAMPTZ,
    finished_at   TIMESTAMPTZ
);
CREATE INDEX idx_step_task ON engine_step(task_id, step_index);

-- 检查点：相位转换前落盘，崩溃/暂停恢复的依据
CREATE TABLE engine_checkpoint (
    id            BIGSERIAL PRIMARY KEY,
    task_id       BIGINT NOT NULL REFERENCES engine_task(id),
    step_id       BIGINT NOT NULL REFERENCES engine_step(id),
    from_phase    TEXT NOT NULL,
    to_phase      TEXT NOT NULL,
    state         JSONB NOT NULL,                   -- 续跑最小状态：相位产出结果+内存上下文
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_ckpt_task ON engine_checkpoint(task_id, id DESC);

-- 审计：每次 LLM 调用一行（成功/重问/失败都记）
CREATE TABLE engine_audit (
    id            BIGSERIAL PRIMARY KEY,
    task_id       BIGINT NOT NULL REFERENCES engine_task(id),
    step_id       BIGINT NOT NULL REFERENCES engine_step(id),
    worker_id     TEXT NOT NULL,
    model         TEXT NOT NULL,                    -- 实际模型串（deepseek:deepseek-chat）
    attempt       INT NOT NULL DEFAULT 0,           -- 第几次 re-ask（0 起）
    result        TEXT NOT NULL,                    -- ok / reask / failed
    input_full    JSONB,                            -- prompt 全文（受控，见 §8）
    output_full   JSONB,                            -- 模型原始输出全文（受控）
    input_tokens  INT,
    output_tokens INT,
    duration_ms   INT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_task ON engine_audit(task_id);
CREATE INDEX idx_audit_worker_day ON engine_audit(worker_id, created_at);
```

队列雏形：v0.1 取任务用 `SELECT ... FOR UPDATE SKIP LOCKED`（为 v0.2 常驻 runner 预演，命令行场景下串行消费），SQL 与锁语义写进测试断言。

# 4. 工序与链的 YAML schema

## 4.1 工序声明（`engine/registry/workers/<域>/<工序>/worker.yaml`）

```yaml
id: chat-translate            # 全局唯一，^[a-z][a-z0-9_]*$
domain: crm                   # 枚举：crm/tm/erp/seo/scrape/demo
version: 1                    # 工序契约版本；output Model 结构变化必须 +1
risk: write                   # 枚举：read/suggest/write；transaction 一律拒载
description: 客户对话翻译与要点提取
input:
  model: ChatTranslateInput   # 必须真实存在于 models/（loader import 校验）
output:
  model: ChatTranslateResult  # 同上；即 PydanticAI 的 output_type
model: default                # 引用 models.yaml 模型别名（禁止内联模型串）
retry:
  max_attempts: 2             # 工序级重试（ACT 副作用/网络，不含 re-ask）
  timeout_s: 30               # 单次 LLM 调用超时
context:                      # 声明要读的 Context provider，必须同域
  - id: crm.customer_history
    params:                   # 查询参数，值来自本工序 input 的字段
      customer_id: input.customer_id
prompt: prompt.md             # 相对本工序目录；模板变量={input.*} {context.*}
config_dir: config/           # 规格外置目录（风格指南/术语表；可为空）
```

## 4.2 链声明（`engine/registry/chains/<域>/<链>/chain.yaml`）

```yaml
id: chat-inbox
domain: crm                   # 链域 = 工序域，不一致拒载
description: 粘贴对话 -> 翻译 -> 快照 -> 待办
input:
  model: ChatInboxInput
steps:
  - worker: chat-translate
    input: task.input         # 省略 input = 整链入参直传
  - worker: snapshot-update
    input:
      conversation: steps[0].output.translated
      customer_id: task.input.customer_id
  - worker: todo-generate
    input:
      snapshot: steps[1].output
```

`steps[n]` / `task.input` 两种引用，loader 静态校验：字段存在、类型对得上（对 Model 字段做静态路径检查），引用后序步（steps[2] 在 step1 里）拒载。

## 4.3 Context provider 声明（`engine/registry/context/<域>.yaml`）

```yaml
- id: crm.customer_history
  domain: crm
  description: 客户近 N 天消息与快照
  params:
    model: CustomerHistoryParams      # 查询参数 Model
  returns:
    model: CustomerHistory            # 返回数据 Model
  provider: crm.customer_history      # web 侧注册的实现标识（v0.1 demo provider）
```

## 4.4 loader 校验规则（不合规拒载，启动失败）

| # | 规则 | 反向测试 |
|---|---|---|
| L1 | 工序/链/provider id 全局唯一、snake_case | 重复 id 拒载 |
| L2 | domain 在枚举内；工序 context 引用的 provider 必须同域 | 跨域引用拒载 |
| L3 | input/output/params/returns 的 model 名必须在 `models/` 可 import | 引用不存在的 Model 拒载 |
| L4 | `model:` 必须是 models.yaml 中已注册别名（**模型串内联拒载**） | `model: deepseek-chat` 拒载 |
| L5 | 链内 worker 必须已注册；链域与全部工序域一致 | 引用未注册 worker 拒载 |
| L6 | 链步骤 input 引用表达式静态可解析、只指向前序 | 引用后序步拒载 |
| L7 | `risk: transaction` 拒载（一期无对外事务） | 声明 transaction 拒载 |
| L8 | prompt 文件、config_dir 必须存在（声明了就要有） | 指向不存在文件拒载 |

# 5. 域权限矩阵与动作风险分级

## 5.1 风险四级（代码规则，AI 不自评）

| 级 | 含义 | 例子 | 门禁 |
|---|---|---|---|
| read | 只分析不落库 | 翻译、摘要 | Policy 直过 |
| suggest | 产出 TaskProposal | 待办建议、补货建议 | 提案全进审核页，人工批（决策 12） |
| write | 写业务库 | 译文写 crm、快照更新 | 写前过业务规则代码校验；幂等 upsert |
| transaction | 对外部系统真实事务 | （一期不存在） | **loader 直接拒载** |

## 5.2 域权限矩阵（v0.1 落地 demo/crm 两行，其余版本到位）

| 域 | 可读 Context | 可写目标 | 风险上限 |
|---|---|---|---|
| demo | demo.* | 无（输出只进引擎库 output 字段） | read |
| crm | crm.* | 业务库 crm schema | write |
| tm | tm.* | tm.proposal（建议，人工审） | suggest |
| erp | erp.*（NocoBase v_* 视图，v0.6 接入） | erp 分析结果表 | suggest |
| seo | seo.* | seo schema | write |
| scrape | scrape.* | scrape schema | write |

越域访问：v0.1 直接拒（L2 校验 + Policy 运行时双保险）。显式跨域声明与审批机制一期不做（无此需求，出现时进详设变更）。

# 6. Business AI Contract 四契约（字段级规范）

落位 `models/contract/`。这是业务模块接引擎的唯一接口，v0.1 定稿后即冻结为公共契约（后续字段变化需走变更日志 + 契约 version+1）。

## 6.1 Event（业务 -> 引擎：「我发生了什么」）

```python
class ContractEvent(BaseModel):
    event_type: str                    # 注册表登记的事件 id，如 crm.message_received
    domain: str                        # crm/tm/erp/seo/scrape
    source: str                        # 发出模块标识，如 web.crm
    occurred_at: datetime              # 事件发生时刻（业务侧时刻，非入队时刻）
    payload: dict[str, Any]            # 须符合该 event_type 声明的 payload Model
    dedup_key: str | None = None       # 去重键：同键在 dedup_window 内不重复触发（v0.4 用）
```

v0.1 只定义类型与登记位（`engine/registry/events/<域>.yaml`），不做消费。事件登记表字段：`event_type / domain / payload Model / dedup_window_min / 触发链`。

## 6.2 Context（业务 -> 引擎：「我能给你看什么」）

两半结构：**声明**（登记进注册表，见 §4.3）+ **实现**（业务侧提供 `async def provide(params: Model) -> Model`，按 provider 标识注册）。引擎运行时按工序声明的 context 列表拉取，域不匹配直接拒绝。Context 是只读供给，实现方保证无副作用。

## 6.3 Action（引擎 -> 业务：「你可以建议我做什么」）

```python
class ActionDeclaration(BaseModel):    # 注册表登记（engine/registry/actions/<域>.yaml）
    action_id: str                     # 如 crm.create_followup_task
    domain: str
    risk: Literal["read", "suggest", "write"]   # transaction 不可登记
    output_model: str                  # 产出数据 Model 名
    target: str                        # 一期唯一合法值：tm.proposal

class ActionResult(BaseModel):         # 引擎运行时产出，随提案走
    action_id: str
    risk: str
    payload: dict[str, Any]            # 须过该 action 声明的 output_model 校验
```

一期 Action 的 target 锁死 `tm.proposal`（loader 校验）：引擎对业务的影响只有一个出口--提案，人工批后才变动作。

## 6.4 Task（引擎 -> TM：「帮我派活给人」）= TaskProposal

```python
class SourceTrace(BaseModel):          # 来源追溯：任何任务能回溯到触发它的 AI 调用
    chain_id: str
    engine_task_id: str                # 展示形 e-000123
    worker_id: str
    audit_ids: list[str] = []          # 支撑结论的 LLM 调用（可回放证据）

class EvidenceRef(BaseModel):          # 依据引用：提案必须可追溯业务事实
    kind: Literal["message", "metric", "order_view", "listing", "image"]
    ref_id: str                        # 业务侧对象 id
    quote: str | None = None           # 原文摘录（如那句要跟进的买家消息）

class TaskProposal(BaseModel):
    title: str = Field(min_length=1, max_length=80)
    detail: str                        # 给执行人看的完整说明
    domain: str
    action_id: str                     # 关联 Action 声明
    suggested_priority: Literal["P0", "P1", "P2", "P3"]   # 建议，人工可改（决策 11）
    suggested_role: Literal["运营", "采购", "管理员"]
    suggested_due_days: int | None     # AI 建议（P0=0/P1=3/P2=7/P3=None），人工可改
    evidence: list[EvidenceRef] = Field(max_items=20)
    source: SourceTrace
```

约束（代码校验，非 AI 自律）：`evidence` 空数组时 `risk: suggest` 的工序不得产出提案（无依据不出建议）；`audit_ids` 非空且可在审计表查到。

# 7. PydanticAI 调用层（`engine/core/llm/`）

## 7.1 模型注册（`models.yaml`，换模型只改这里）

```yaml
models:
  default:
    provider: deepseek
    model: deepseek-chat
    base_url: env:DEEPSEEK_BASE_URL    # env: 前缀 = 启动时从环境变量读，文件里永不出现真值
    api_key: env:DEEPSEEK_API_KEY
    timeout_s: 30
    reask_limit: 2
```

对 LLM 的调用全仓只允许出现在 `engine/core/llm/`（lint P2/P3 联合执法）。模型串永不内联（规范 R11）。

## 7.2 重试/超时/降级三级策略（技术定）

| 层级 | 触发 | 动作 | 上限 |
|---|---|---|---|
| 1. re-ask | 输出不过 output_type 校验 | PydanticAI 自动带错误信息重问 | 2 次（reask_limit） |
| 2. 工序重试 | 网络错误 / 超时 / 5xx | 指数退避 5s→30s 后重调 | 2 次（max_attempts） |
| 3. 链失败 | 前两层耗尽 | 工序 FAILED -> 链 FAILED，任务带显式原因终态 | 人工 resume 重跑 |

**无静默降级**：一期无备模型，DeepSeek 不可用 = 任务 FAILED + 显式原因，不产任何假结果（与「宁失败不假成功」同哲学）。models.yaml 预留多模型位（fallback 键），启用与否 v0.3 后按故障率再议。

## 7.3 用量记录

每次调用从 PydanticAI `RunUsage` 取 input/output tokens、耗时毫秒，连同 result 状态写 `engine_audit`。审计不可写 = 调用不允许发生（先审计后调用的顺序约束，写进测试）。

# 9. lint 三规则细则（`engine/lint/`，可判定）

对象与豁免写死在规则配置里，验收 = 每规则一正一反测试。

**P1 业务词黑名单**
- 对象：`engine/workers/`、`engine/registry/`（.py 与 .yaml）
- 规则：业务规格值（专名/字段清单/数量规格）不得以字面量出现在代码，必须住进工序 `config/`；词表 = 基础词表（人工维护）∪ 自动生成（扫各 config/ 的键与值产生的专名），重复扫 = 词表自动生长
- 判定样例：`"13"` 个标签、飞书列名、店铺名出现在 run.py → fail

**P2 凭据端点零容忍**
- 对象：除 `engine/core/llm/`、`tests/fixtures/`、`scripts/` 外的全部 .py
- 规则：URL/IP 字面量、`sk-` 前缀串、`api_key|password|token` 赋值语句、`.env` 之外读取环境变量的绕路 → fail
- 唯一合法来源：models.yaml 的 `env:` 前缀 + `.env` 文件

**P3 契约纪律**
- 规则 1：工序函数签名必须 `run(inputs: RegisteredModel, ctx: EngineContext) -> RegisteredModel`；返回裸 dict / 未登记 Model → fail
- 规则 2：`web/` 与 `scripts/` 不得 import `engine.workers.*` / `engine.core.*`（web 只能走三接口；v0.1 先落 import 检查器，web 目录 v0.2 出现后生效）
- 规则 3：`models.yaml` 中出现真实密钥值（非 `env:` 前缀）→ fail

lint 结果进 `scripts/check.sh` 的四绿之一（开发流程 ④）。
