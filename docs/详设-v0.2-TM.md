# 1. 范围

v0.2 交付「**AI 建议自动变任务，人工处理完回流**」的端到端闭环（任务生成双通道，决策 16）：

```text
AI 通道：人工触发演示链 -> 引擎跑链产出 TaskProposal（依据强制 + 禁幻觉三件套校验）
          -> 提案落业务库待审核 -> 人工批/驳（全部人工审，决策 12）
          -> 批准成任务 -> 人工处理 -> 状态回流（task_event 流水 + 追溯闭环）
人工通道：任务中心「新建任务」直接落 tm.task（source_type=manual，来源域可选）
```

- **任务来源**（决策 16）：CRM / ERP / SEO 等业务系统 + 任务系统本身（tm）；task.domain 标来源域，列表按域显示来源徽章。
- **AI 提案审核依据**（决策 16）：审核面板强制展示每条依据（类型+业务对象 id+原文摘录）与查看入口；AI 可引用数据受链数据白名单封闭，100% 禁止幻觉（机器校验拒落）。

明确不包含（后续版本）：统计页真实内容（决策 15：方向已定、内容后续在定）、任务中心二级菜单填充（机制已预留）、CRM/ERP/SEO/扒图真实业务（v0.3/v0.5/v0.6）、循环任务（v0.4 定时链）、事件触发与配额记账（v0.4）、复杂权限（一期从简：共享密码 + 三角色）。


# 3. 业务库表结构（database: liuquan, schema: tm）

## 3.1 tm.task 任务表

```sql
CREATE TABLE tm.task (
    id            BIGSERIAL PRIMARY KEY,          -- 展示形 t-<6位零填充>
    title         TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 80),  -- 对齐 TaskProposal.title
    detail        TEXT,                            -- 给执行人的完整说明（人工任务可空）
    domain        TEXT NOT NULL,                   -- 来源业务域：crm/erp/seo/tm/...（任务来源标徽章，决策 16）
    role          TEXT NOT NULL CHECK (role IN ('运营','采购','管理员')),  -- 负责人按角色指派
    due           DATE NOT NULL,                   -- 截止：手填 + AI 建议可改（决策 11）
    status        TEXT NOT NULL DEFAULT 'open'
                  CHECK (status IN ('open','in_progress','done','void','blocked')),  -- 五态
    blocked_reason TEXT,                           -- status=blocked 时必填（CHECK 见下）
    source_type   TEXT NOT NULL CHECK (source_type IN ('ai','manual')),  -- ai=提案批准 / manual=人工创建
    source        JSONB NOT NULL,                  -- 来源追溯（§3.4）
    created_by    TEXT NOT NULL CHECK (created_by IN ('运营','采购','管理员')),  -- 创建人角色
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    done_at       TIMESTAMPTZ,                     -- 勾选完成时写入（统计/回流用）
    CONSTRAINT chk_blocked_reason CHECK (
        (status = 'blocked' AND blocked_reason IS NOT NULL)
        OR (status <> 'blocked' AND blocked_reason IS NULL)
    )
);
CREATE INDEX idx_task_status_due ON tm.task(status, due);
CREATE INDEX idx_task_role ON tm.task(role);
```

**字段说明（对应建设方案 v0.2 TM 数据模型细则，2026-08-28 修订版）：**

| 字段 | 规则 | 依据 |
|---|---|---|
| domain | **来源业务域**：crm / erp / seo / tm（任务系统自身）/ 其他；AI 任务继承提案 domain，人工任务创建时选择。任务列表按域标来源徽章——"这任务是谁提的"一眼可见 | 决策 16 |
| role | 按角色（运营/采购/管理员）指派；AI 提案按工序域带默认角色，批准时可改 | 决策 11 |
| due | 截止手填 + AI 建议（suggested_due_days）可改；**逾期标红**（status 非 done/void 且 due < 今天） | 决策 11 修订 |
| status | 五态 open/in_progress/done/void/blocked；**无优先级分级**（无 P0-P3，无逾期自动升级） | 决策 11 修订 |
| blocked_reason | status=blocked 时必填，取值「等物料 / 等回复」二选一（⚑ 枚举先固定这两个，业务后续要加走变更日志加 CHECK 值） | 决策 11 |
| source_type / source | 来源追溯：**AI 生成**（提案批准，可回溯到引擎调用）或**人工输入**（直接建任务，creator 即依据） | 决策 16 |

## 3.2 tm.task_proposal 提案表（AI 提案全部人工审，决策 12）

```sql
CREATE TABLE tm.task_proposal (
    id               BIGSERIAL PRIMARY KEY,       -- 展示形 p-<6位零填充>
    title            TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 80),
    detail           TEXT NOT NULL,               -- 给执行人的完整说明（TaskProposal.detail）
    domain           TEXT NOT NULL,               -- 工序域（crm/erp/seo/...，TaskProposal.domain）
    action_id        TEXT NOT NULL,               -- 关联 Action 声明（TaskProposal.action_id）
    risk             TEXT NOT NULL CHECK (risk IN ('read','suggest','write')),
                                                   -- 风险级：代码规则标注（域+动作类型查表），非 AI 自评
    suggested_role   TEXT NOT NULL CHECK (suggested_role IN ('运营','采购','管理员')),
    suggested_due_days INT,                       -- AI 建议截止天数（独立建议，人工可改，无分级映射）
    evidence         JSONB NOT NULL DEFAULT '[]', -- EvidenceRef 数组：kind/ref_id/quote（对齐契约 §6.4）
    source           JSONB NOT NULL,              -- SourceTrace：chain_id/engine_task_id/worker_id/audit_ids
    status           TEXT NOT NULL DEFAULT 'pending'
                     CHECK (status IN ('pending','approved','rejected')),  -- 审核态三态
    reviewed_by      TEXT,                        -- 审核人角色
    reviewed_at      TIMESTAMPTZ,
    reject_reason    TEXT,                        -- 驳回理由（status=rejected 时建议填，不强制）
    task_id          BIGINT REFERENCES tm.task(id),  -- 批准后关联生成的任务（业务库内 FK，合法）
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_proposal_status ON tm.task_proposal(status, created_at DESC);
```

**审核流（决策 12：全部人工批/驳，不设代码自动通过；决策 16：审核依据强制展示 + 禁止幻觉）：**

```text
链完成 -> 引擎转交器把 TaskProposal 落 tm.task_proposal（status=pending）
  -> 任务中心「待审核」栏展示：
       ① 提案标题/详情/来源（域 + 链 + 引擎任务 id）
       ② 风险级徽章（代码规则标注）
       ③ 【依据区】每条 evidence 完整列出：类型(消息/指标/订单/listing/图片)
          + 业务对象 id + 原文摘录 quote —— 审核人据此判断 AI 不是瞎说
       ④ 【查看入口】证据点「查看」跳对应业务系统上下文页
          （v0.2 业务系统未建：展示依据全文 + ref_id，跳转机制预留，
           CRM/ERP 落地时各业务域注册 evidence 查看 URL 解析器）
       ⑤ 【审计兜底】点来源 audit id -> 引擎库可查那次 LLM 调用输入输出
  -> 人工点「批准」：事务内
       提案 status=approved + reviewed_by/reviewed_at
       + 新建 tm.task（source_type=ai，domain=提案 domain，source 复制提案来源并追加 proposal_id）
       + task.source.proposal_id 回填提案 task_id
       + task_event 记 created + approved 两条
  -> 人工点「驳回」：status=rejected + reject_reason，不建任务
```

**禁止幻觉三件套（机器强制，不是 AI 自觉；违反任一 -> 转交器拒落 + 链标 FAILED）：**

| # | 校验 | 说明 |
|---|---|---|
| 1 | evidence 非空 | 无依据不出建议（详设 v0.1 §6.4，v0.1 已立） |
| 2 | audit_ids 可查 | 每个 audit_id 能在引擎库查到对应 LLM 调用（详设 v0.1 §6.4） |
| 3 | **数据引用封闭性（新增，决策 16）** | evidence 的每个 ref_id 必须来自**本链实际喂给 AI 的数据集合**（链 Context provider 提供的对象 id 白名单）——AI 只能引用它真看过的数据；引用未喂给它的业务对象 = 拒落 |

**幂等（技术定）**：转交器按 `source.engine_task_id + worker_id` 去重——同一链同一工序的提案重复交付（runner 重试/重跑）只落一条；已存在则跳过（不重复建任务）。

## 3.3 tm.task_event 状态流水表

```sql
CREATE TABLE tm.task_event (
    id          BIGSERIAL PRIMARY KEY,
    task_id     BIGINT NOT NULL REFERENCES tm.task(id) ON DELETE CASCADE,
    event_type  TEXT NOT NULL CHECK (event_type IN
                ('created','approved','started','completed','voided','blocked','unblocked','updated')),
    from_status TEXT,                              -- 迁移前状态（创建事件为空）
    to_status   TEXT,                              -- 迁移后状态
    actor       TEXT,                              -- 操作者角色
    note        TEXT,                              -- 备注（如 blocked_reason）
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_event_task ON tm.task_event(task_id, created_at);
```

**事件写入点（代码写死，不依赖 AI）：**

| 事件 | 触发 |
|---|---|
| created | 任务创建（人工建任务 / 提案批准建任务） |
| approved | 提案批准（与 created 同事务） |
| started | open -> in_progress |
| completed | -> done（写 done_at） |
| voided | -> void |
| blocked / unblocked | <-> blocked（blocked 时 note=blocked_reason） |
| updated | 其余字段修改（title/role/due） |

**回流语义（v0.2 形态，技术定）**：任务完成/作废 = task_event 落库（业务库内的完整事实流水），这是 v0.4 事件触发的数据基础（留位）；「引擎可查」在本版落实为**追溯闭环**——从任务可回溯到提案 → 引擎任务（engine_task_id）→ 引擎审计（audit_ids 可在引擎库查到全部 LLM 调用）。任务完成后结果事件回引擎的完整闭环（event_subscription）在 v0.4 落地，v0.2 不新增引擎接口。

## 3.4 source 追溯结构（JSONB，对齐四契约 SourceTrace）

```jsonc
// source_type = 'ai' 时（domain 独立字段 = 提案 domain，见 §3.1）
{
  "chain_id": "tm_demo_chain",
  "engine_task_id": "e-000001",   // 展示形
  "worker_id": "demo_propose",    // 产出本提案的工序
  "audit_ids": ["<审计 id>"],     // 支撑结论的 LLM 调用（引擎库可查）
  "proposal_id": "p-000001"       // 批准时回填
}
// source_type = 'manual' 时（domain 独立字段 = 创建时选的来源域）
{ "creator": "运营" }
```

# 4. 引擎三接口（web 只经这三接口碰引擎，承概设 §3.3）

宿主：`engine/server.py` 的 FastAPI app，前缀 `/api/engine`。web 用异步 HTTP 客户端调用（base URL 来自 `.env`）。

## 4.1 POST /api/engine/tasks —— 人工触发一个工序链

```text
请求: {"chain_id": "tm_demo_chain", "input": {...}, "trigger_ref": "运营"}
响应 201: {"task_id": "e-000001", "status": "queued", "chain_id": "tm_demo_chain"}
错误 404: {"detail": "chain not registered"}        # 链未登记
错误 422: {"detail": "<input 校验错误明细>"}          # 入参不过链 input Model
```

- 服务端行为：建 engine_task 入队（trigger_type=manual，trigger_ref=操作者角色），立即返回 201；实际执行由常驻消费循环异步完成（页面侧轮询 GET 查终态）。
- 与 CLI `liuquan-engine run` 同源（同一建任务+入队函数，技术定：CLI 保留作运维/测试入口）。

## 4.2 GET /api/engine/tasks/{id} —— 查状态/结果

```text
响应 200:

  "current_step": 2, "error": null,
```

# 5. 引擎侧新增：TM 转交器（Action 消费者，技术定）

引擎不直接写业务库——链完成后由**注册的 Action 消费者（纯代码）**把 TaskProposal 落业务库，AI 全程不碰库（AI 100% 可控，承最高原则）。

```text
engine/actions/tm_proposal.py    TM 转交器：消费 ActionDeclaration(target="tm.proposal")
                                  链完成回调 -> 校验 TaskProposal（Pydantic + 业务校验）
                                  -> 幂等去重 -> 写 tm.task_proposal（status=pending）
engine/actions/__init__.py       消费者注册表（v0.2 仅 tm.proposal 一条）
```

- 写库用 SQLAlchemy 独立连接（`.env` 的 `LIUQUAN_TM_DB_URL`，只写 tm schema 的专用权限），不 import web 任何代码。
- **业务校验三件套（代码，非 AI 自律，承详设 v0.1 §6.4 + 决策 16）：**
  1. `evidence` 空数组拒落（无依据不出建议）；
  2. `audit_ids` 非空且每个 id 可在引擎库查到对应 LLM 调用（追溯保证）；
  3. **数据引用封闭性**（决策 16，禁止幻觉）：evidence 的每个 `ref_id` 必须命中**本链喂给 AI 的数据集合**（链 Context provider 声明的对象 id 白名单）——AI 只能引用它真看过的数据；引用白名单外的业务对象 = 拒落 + 链 FAILED（error 记「幻觉证据: ref_id=...」）。
- 业务表 ORM 声明住 `models/tm.py`（纯数据层，无业务逻辑；web 与转交器共用同一 Model，承 R22 唯一通用语言）。

```text
链 id: tm_demo_chain（demo 域，v0.2 演示用）
工序序列:
  1. demo_echo         已有工序（v0.1，桩驱动冒烟）：echo 输入 -> 结构化输出
  2. demo_propose      新增代码工序（无 LLM 调用）：把 echo 结果组织成 TaskProposal
                       输出 Model = TaskProposal 契约（域 demo / action tm.proposal / 默认角色按工序声明）
链完成 -> 转交器落 tm.task_proposal(pending) -> 页面待审核栏可见
```

- demo_propose 是**纯代码工序**（不调 LLM），演示「AI 建议 -> 提案 -> 任务」闭环而不增加 token 成本；其产出提案**必须带 evidence**（引用链输入的原始文本/指标，演示数据引用封闭性校验路径）；v0.3 起真实业务工序（crm_translate 等）产出提案走同一条转交链路（引擎零改动，承四契约扩展机制）。
- 真调 DeepSeek 的演示链后续按需加（v0.1 翻译雏形已探路）。

# 10. 决策点

**技术方已定（授权范围内，无异议即执行）：**
- 常驻形态：engine/server.py 单进程 = 三接口 + 队列消费循环；并发上限 2；systemd 双服务
- TM 转交器（Action 消费者）模式：引擎不直接写业务库，链完成由注册消费者代码落库；幂等去重
- 业务表 ORM 住 models/tm.py（web 与转交器共用，R22）
- web 只经 HTTP 三接口碰引擎，双向零代码耦合（P3-2 延续）
- 回流 v0.2 形态 = task_event 流水 + 追溯闭环；完整事件闭环 v0.4
- 禁止幻觉三件套（§3.2/§5）：数据引用封闭性白名单 = 链 Context provider 声明的对象 id 集合

**已拍板（业务方确认）：**
1. 无优先级分级（决策 11 修订，2026-08-28）：无 P0-P3、无逾期自动升级；逾期标红保留；有分级标准后 AI 按标准分级再议
2. 全部 AI 提案人工审（决策 12，2026-08-27）：不设代码自动通过
3. 统计数据一定会做、工作台当前无内容（决策 15，2026-08-28）：统计页内容后续在定
4. 导航结构（2026-08-28）：工作台一级无内容 / 任务中心一级+预留二级 / CRM·ERP 二级占位 / SEO·扒图一级占位
5. TM 细则（决策 11 原版，2026-08-27 保留部分）：按角色指派 / 截止手填+AI 建议 / 五态+blocked / 循环任务交 v0.4 定时链
6. **任务生成细则（决策 16，2026-08-28）**：任务生成双通道（AI 生成 + 人工输入）；任务来源 = 业务系统（CRM/ERP/SEO 等）+ 任务系统自身（task.domain 标来源徽章）；AI 提案审核时依据强制展示（每条 evidence 类型+ref_id+原文摘录 + 查看入口），AI 可引用数据受白名单封闭（100% 禁止幻觉，机器校验拒落）
