# 3. crm schema 四表（database: liuquan, schema: crm）

> 字段对齐 EOMS（app/models.py）已验证结构 + 刘全需求修订（决策 19/23/24/25）。ORM 住 `models/crm.py`（复用业务库 declarative base，v0.2 `models/tm.py` 的 `TmBase`，R22）。

## 3.1 crm.customer 客户表

```sql
CREATE TABLE crm.customer (
    id               BIGSERIAL PRIMARY KEY,
    nickname         TEXT NOT NULL CHECK (length(nickname) BETWEEN 1 AND 255),  -- 重名忽略大小写精确匹配
    source_shop      TEXT NOT NULL DEFAULT '',          -- 来源店铺
    remark           TEXT NOT NULL DEFAULT '',          -- 备注
    follow_up_status TEXT NOT NULL DEFAULT 'waiting_reply'
                     CHECK (follow_up_status IN ('waiting_reply','replied','closed_deal','on_hold','archived')),
    trade_stage      TEXT NOT NULL DEFAULT 'pre_sale'
                     CHECK (trade_stage IN ('pre_sale','in_sale','after_sale')),
    order_no         TEXT NOT NULL DEFAULT '',          -- 订单号备注（可空语义 = 空串）
    latest_summary   TEXT,                              -- 冗余：最新快照 summary（页面层维护）
    last_contacted_at TIMESTAMPTZ,                      -- 最新操作时间（粘贴归档/回复发送刷新）
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_crm_customer_status ON crm.customer(follow_up_status);
CREATE INDEX idx_crm_customer_updated ON crm.customer(updated_at DESC);
```

**说明**：
- 状态五值/阶段三值与 EOMS 一致；`archived` 不参与逾期判定、默认列表不展示。
- 逾期语义（EOMS 验证）：`latest_activity = max(last_contacted_at, updated_at)`，超过 `FOLLOW_UP_DAYS`（config 外置，默认 5）天无动静 = 逾期标红。归档客户不判定。

## 3.2 crm.message 对话消息表

```sql
CREATE TABLE crm.message (
    id              BIGSERIAL PRIMARY KEY,
    customer_id     BIGINT NOT NULL REFERENCES crm.customer(id) ON DELETE CASCADE,
    source_text     TEXT NOT NULL,                      -- 原文
    translated_text TEXT NOT NULL DEFAULT '',           -- 中文译文
    direction       TEXT NOT NULL CHECK (direction IN ('buyer','seller')),
    language        TEXT NOT NULL DEFAULT '',           -- 原文语种
    message_time    TIMESTAMPTZ,                        -- 可空：粘贴场景不标（决策 23）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_crm_message_customer ON crm.message(customer_id, created_at);
```

**说明**：append-only（只插入不更新）；时间线提供人工删除口（误贴清理，v0.3 平移）。**message_time 一律留空**（决策 23：历史记录/正常粘贴均不标时间）。

## 3.3 crm.snapshot 客户快照表（滚动快照机制平移）

```sql
CREATE TABLE crm.snapshot (
    id            BIGSERIAL PRIMARY KEY,
    customer_id   BIGINT NOT NULL REFERENCES crm.customer(id) ON DELETE CASCADE,
    current_need  TEXT NOT NULL DEFAULT '',
    need_history  JSONB NOT NULL DEFAULT '[]',          -- list[str]，需求变更史只增不减
    sentiment     TEXT NOT NULL DEFAULT '',
    todos         JSONB NOT NULL DEFAULT '[]',          -- list[str]，历史候选摘要（供防重/上下文）
    summary       TEXT NOT NULL DEFAULT '',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_crm_snapshot_customer ON crm.snapshot(customer_id, created_at DESC);
```

**说明**：
- 版本化：每客户多行，取 created_at 最新一行为当前快照（EOMS 验证语义）。
- `todos` 字段保留（对齐广成交付物结构）：AI 滚动总结时携带的待办摘要列表，供 todo_generate 防重与上下文；**不是任务实体**（任务实体 = tm.task + crm.todo_candidate）。
- 不建 EOMS 的 `reply_draft` 列（已废弃写空串，刘全新库不建）。

## 3.4 crm.todo_candidate 待办候选表（决策 19/25）

```sql
CREATE TABLE crm.todo_candidate (
    id              BIGSERIAL PRIMARY KEY,
    customer_id     BIGINT NOT NULL REFERENCES crm.customer(id) ON DELETE CASCADE,
    content         TEXT NOT NULL CHECK (length(content) BETWEEN 1 AND 200),  -- 中文动宾短语
    reason          TEXT NOT NULL DEFAULT '',           -- 生成依据（一句话，给人看）
    suggested_tags  JSONB NOT NULL DEFAULT '[]',        -- AI 建议标签 list[str]（决策 25，确认时写入 tm.task.tags）
    evidence        JSONB NOT NULL,                     -- EvidenceRef[] 对齐四契约（type/ref_id/quote，决策 16）
    status          TEXT NOT NULL DEFAULT 'pending'
                    CHECK (status IN ('pending','confirmed','dismissed')),  -- confirmed=已转任务
    engine_task_id  BIGINT,                             -- 来源引擎任务（追溯，跨库不建 FK）
    confirmed_task_id BIGINT,                           -- 确认后生成的 tm.task id（追溯，同库可建 FK 但按 R23 走声明）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    confirmed_at    TIMESTAMPTZ,
    dismissed_at    TIMESTAMPTZ
);
CREATE INDEX idx_crm_candidate_customer ON crm.todo_candidate(customer_id, status);
CREATE INDEX idx_crm_candidate_status ON crm.todo_candidate(status, created_at DESC);
```

**说明**：
- `evidence` 非空强制（决策 16 禁幻觉①：无依据候选不可确认——DB CHECK `chk_candidate_evidence`：`jsonb_array_length(evidence) > 0`；页面层 + 引擎消费者双层校验）。
- 防重：同一 customer_id 下 status=pending 的候选，页面确认后置 confirmed；**重复确认拒**（confirmed 状态不可再确认，应用层 + DB 检查）。
- `confirmed_task_id`：确认事务内回填 tm.task id（追溯闭环：候选 -> 任务）。

# 4. tm 侧扩展（迁移 0003）

## 4.1 tm.task 加两列（决策 25/27）

```sql
ALTER TABLE tm.task ADD COLUMN tags JSONB NOT NULL DEFAULT '[]';
ALTER TABLE tm.task ADD COLUMN ai_suggestion JSONB;
```

| 列 | 规则 | 依据 |
|---|---|---|
| tags | 开放标签数组（list[str]），校验：元素 1-30 字符、去重、最多 20 个；AI 生成任务时写入 suggested_tags（决策 25），人工编辑可改可删（updated 事件带 from/to 快照，v0.2 编辑机制扩展） | 决策 25 |
| ai_suggestion | AI 下一步建议（决策 27），**来源 = todo_generate 候选的 suggested_next**（确认建任务时写入，§5.1/§8.1）；结构：`{action, target_domain?, target_role?, tags?, note, suggested_at, engine_task_id?}`；action ∈ transfer/assign/tag/note/block；页面「下一步」区展示为默认建议；人工可改/清 | 决策 27 |

## 4.2 tm.task_event 扩展（决策 27/28 流转留痕）

```sql
ALTER TABLE tm.task_event ADD COLUMN detail JSONB;  -- 结构化详情（from/to/note/指令解析）
-- event_type CHECK 由 9 值扩为 12 值：
-- 'created','approved','started','completed','voided','blocked','unblocked','derived','updated'
-- + 'suggested'（AI 建议写入 ai_suggestion）/ 'transferred'（流转执行：改派/打标签/挂起/指令执行）
-- + 'disagreed'（分歧留痕：AI 建议 vs 人选择，detail 记两者）
```

- `suggested`：AI 建议生成/更新时写入（note = 建议摘要，detail = ai_suggestion 快照）。
- `transferred`：人执行流转时写入（from/to_status 沿用；detail = {action, target, note}；actor = 操作角色）。
- `disagreed`：人选择与 AI 建议不同时写入（detail = {ai_suggestion, human_chose}，决策 27 分歧留痕）。

## 5.1 工序与 Model（models/workers/ 新增，P3-1 契约）

| 工序 id | 域 | risk | reason | input Model | output Model | 说明 |

| tm_intent（新） | tm | suggest | llm | IntentInput {**task_id: int**, instruction: str} | IntentResult {action: Literal['transfer','assign','tag','note','block'], target_domain: str\|None, target_role: str\|None, tags: list[str]\|None, note: str\|None, clarity: Literal['clear','unclear'], candidates: list[str]\|None} | **流转自然语言入口**（决策 28）：把自然语言指令解析为结构化流转指令；任务上下文走 tm_task_context provider |

**SuggestedNext（todo_generate 候选的下一步建议，决策 27 产出机制）**：`{action: Literal['transfer','assign','tag','note'], target_domain: str\|None, target_role: str\|None, tags: list[str]\|None, note: str\|None}`——AI 在生成候选时**顺带建议该任务生成后的下一步**（如「建议流转到 ERP 生成采购申请」「建议指派给采购」）；**确认建任务时写入 tm.task.ai_suggestion + suggested 事件**（§8.1 第 3b 步）；人工可在任务「下一步」区改/清。**动作集合与 IntentResult（§5.1 tm_intent）对齐**，v0.3 可执行 = assign/tag/note（transfer 目标域未接入时明确提示不可执行并记录意图，决策 28）。

**技术定（开发启动修订）**：`ReplyDraftInput`/`IntentInput` 必须带业务对象 id（customer_id / task_id）——Context provider 的查询参数值来自本工序 input 字段（详设 v0.1 §4.1 机制：`params: {customer_id: input.customer_id}`），input 无 id 则无法拉取上下文（crm_chat_context / tm_task_context）。ChatTranscriptInput（含 customer_id）不受影响。

**技术定（集成验收修订）**：`todo_generate` 对「每条候选必带结构化 evidence（ref_id 引用消息 id）」的 LLM 执行不稳定（真实对话候选频繁为空）——缺 evidence 的候选由**代码**补引用最近一条买家消息作 evidence（AI 真看过该消息 = 白名单内，决策 16③ 数据引用封闭性仍满足；evidence 机器生成可追溯，非 AI 自证；无消息可引用时剔除，全空 = 合法空数组）。

**技术定（T4 开发修订）**：`SnapshotUpdateInput`/`TodoGenerateInput` 也补 `customer_id`——三工序链步骤 input 映射（chain.yaml `customer_id: task.input.customer_id` 透传）需要目标字段存在于工序 input Model（loader L6 静态检查），且 provider params 引用 input.customer_id；**policy 增启用 tm 域**（tm_intent 工序/tm_task_context provider 属 tm 域，详设 v0.1 §5.2 实际启用集由 {demo, crm} 扩为 {demo, crm, tm}）。

**工序 config/（规格外置，R10）**：
- `chat_translate/config/风格指南.md` + `术语表.md`：承接广成 customer-chat-extract 的 config（原样平移，改配置不改代码）。
- `customer_reply_draft/config/风格指南.md`：承接广成 customer-reply-draft 的 config。
- `todo_generate/config/rules.yaml`：提炼规则（只列卖家明确承诺的动作/与已有待办语义相同不重复/拿不准不列/空数组合法）。
- `tm_intent/config/actions.yaml`：可解析动作清单 + 各动作的提示语模板。

**禁幻觉三件套（决策 16，转交器/消费者层机器校验，AI 不参与）**：
1. evidence 非空拒落；
2. audit_ids 可查（reason=llm 必须有）；
3. **数据引用封闭性**：evidence 每个 ref_id 必须命中本链数据白名单（= crm_chat_context provider 返回的 id 集合：customer.id + messages[].id + snapshot.id）。

## 5.2 Context provider（v0.1 机制正式启用）

```yaml
# engine/registry/context/crm.yaml
- id: crm_chat_context            # loader L1：snake_case
  domain: crm
  params:
    model: ChatContextParams       # {customer_id: int}
  returns:
    model: ChatContextData         # {customer, messages[], snapshot?, existing_open_todos[]}
  provider: crm.chat_context       # 实现标识（web 数据 -> 引擎侧 HTTP 实现）

# engine/registry/context/tm.yaml
- id: tm_task_context
  domain: tm
  params:
    model: TaskContextParams       # {task_id: int}
  returns:
    model: TaskContextData         # {task, tags, recent_events[]}
  provider: tm.task_context
```

**Model（models/workers/）**：
- `ChatContextData {customer: CustomerBrief, messages: list[MessageBrief], snapshot: SnapshotBrief|None, existing_open_todos: list[str]}`；`CustomerBrief {id, nickname, latest_summary}`；`MessageBrief {id, source_text, translated_text, direction}`；`SnapshotBrief {id, current_need, need_history, sentiment, todos, summary}`。
- `TaskContextData {task_id, title, domain, status, tags, recent_events: list[EventBrief]}`；`EventBrief {event_type, note, created_at}`。

**provider 实现（引擎侧，决策 26 读取接口化）**：`engine/providers/crm.py` + `engine/providers/tm.py`——HTTP 客户端调 web 只读接口（§6），`trust_env=False`（防系统代理坑，v0.2 engineapi 同款），凭证 `LIUQUAN_BIZ_API_TOKEN`；装配进 runner 的 `providers` 注入（v0.1 §13 构造注入点，测试注入 fake 实现）。

**白名单正式化（决策 16 ③）**：runner REASON 组装时，provider 返回数据即链白名单来源——`whitelist = {customer.id, *messages[].id, snapshot.id}`（chat 链）或 `{task_id}`（intent 链）；消费者校验 evidence ref_id 命中（v0.2 简化白名单机制升级为 provider 声明来源）。

# chains/crm/crm_translate_chain（已有 v0.1，保留给翻译工具，不动）

# 6. 业务写入/读取接口规范（决策 26）

> web 侧 `web/api_biz.py`。全部为**内部接口**（引擎经 HTTP 调用），`X-Biz-Token` 鉴权（`.env` 的 `LIUQUAN_BIZ_API_TOKEN`，双方共享；请求头缺失/不匹配 -> 401）。接口**不区分调用方是 AI 还是人**，只做数据正确性校验（Pydantic 类型 + 业务规则），正确即入库（用户拍板）。

| 方法 | 路径 | 用途 | 请求体 -> 响应 |
|---|---|---|---|
| POST | /api/biz/tm/proposals | 转交器落提案 | TaskProposalWrite（对齐四契约 TaskProposal + source）-> {ok, id} / {ok: false, error} |
| POST | /api/biz/crm/candidates | 候选消费者落候选 | TodoCandidateWrite（content/reason/suggested_tags/evidence/source）-> {ok, id} / {ok: false, error} |
| GET | /api/biz/crm/context/{customer_id} | 引擎侧 provider 读上下文 | -> ChatContextData JSON（白名单来源） |
| GET | /api/biz/tm/task-context/{task_id} | 引擎侧 provider 读任务上下文 | -> TaskContextData JSON |

- 幂等：写入接口按请求体 source.engine_task_id + worker_id 幂等（沿用 v0.2 转交器幂等语义，移到接口层双保险）。
- 校验失败 -> 422（detail 带违规点）；鉴权失败 -> 401；未登记资源 -> 404。
- `.env.example` 增：`LIUQUAN_BIZ_API_URL` / `LIUQUAN_BIZ_API_TOKEN`（R20 只留名）。

## 7.2 客户详情页要素（对齐 EOMS crm/detail.html 三行布局）

1. **快照通栏**：最新快照（current_need/need_history/sentiment/summary）+ 更新时间 + 逾期提示（超过 FOLLOW_UP_DAYS 无动静标红）。
2. **收件粘贴 + 回复台**：粘贴框（conversation_text）+ 翻译按钮（异步轮询进度：提交即返回 engine_task_id，JS 轮询 GET /api/engine/tasks/{id} 代理，终态后刷新）；回复台（mode 三选 + points/full_text 输入 + 生成 + 双栏预览 + 已发送归档）。
3. **时间线**：消息流（direction 徽章/原文/译文/时间）+ 新落库高亮 + 单条删除。
4. **任务卡**（决策 24）：`tm.task WHERE domain='crm' AND source->>'customer_id' = X` 过滤视图——状态/截止/负责人/标签/来源徽章 CRM；逾期标红；**「下一步」区**（§7.3）。

## 7.3 任务「下一步」区（决策 27/28，任务中心 tasks.html + 客户详情任务卡共用）

- **AI 建议卡**：读 tm.task.ai_suggestion 展示（"AI 建议：流转到 ERP 生成采购申请" 等）；无建议不显示。
- **操作**：`同意`（按建议执行——v0.3 可执行动作 = assign/tag/note/block；transfer 目标域未接入 -> 明确提示不可执行并记录意图，决策 28）、`改派`（改 role/tags，updated 事件）、`忽略`（清 ai_suggestion + 记 note）。
- **自然语言输入框**："用一句话告诉 AI 下一步做什么，如『流转到 ERP 库存』『交给采购』『挂起等物料』"——提交 -> 触发 tm_intent_chain -> 页面展示解析结果（action/target/note）+ `确认执行` / `重新输入`；clarity=unclear -> 展示 candidates 让用户澄清（不猜测执行，决策 28）；解析失败 -> 友好错误。
- **分歧留痕**：人选择与 AI 建议不同 -> task_event 写 disagreed（detail 记 ai_suggestion vs human_chose，决策 27）。
