# 1. 范围

v0.4 交付「**定时闭环 + 设置页（配置地基）**」：①先立配置地基——settings 表 + 设置页，让所有参数都从设置里读，杜绝硬编码继续滋生；②系统第一次不需要人触发自己干活——定时自动检查、提醒任务自动就位 TM。

```text
配置地基（决策 34/36）
  sys.settings 表（键值对，读配置先查表、表无回退默认） + get_setting 统一封装
  -> 现有硬编码全量搬入（crm.follow_up_days / crm.page_size / schedule.default_time /
     engine.max_attempts / engine.timeout_s / engine.backoff_cap / notify.feishu_enabled）

设置页五项（决策 33/34/35/36，导航一级「设置」）
  AI 设置（分组标题不可点 + 叶子菜单：API 密钥[做] / 模型选择[占位] / 风格指南术语表[占位]）
  店铺管理（sys.shop 表 + 增改启停删；CRM source_shop 下拉候选）
  定时任务（schedule 链清单 + 新增/启停/改时间/立即运行）
  通知配置（全局总开关 + 飞书 webhook URL 写 .env）
  系统参数（每个键独立存/独立提交）
  == 独立提交机制（决策 36）：每块独立小表单 + 独立接口 + HTMX 局部刷新，settings 按 key 原子更新 ==

定时触发底座（引擎，决策 33）
  schedule 表（引擎库）+ 调度器（engine/server.py 常驻 tick）+ 去重（决策 17 防重语义）
  -> 引擎接口扩展（web 经 HTTP 管理定时链）

首批定时链 1 条（决策 33/37）
  crm_reminder_chain：CRM 客户超 N 天未跟进提醒（每天自动跑）
  -> 纯代码生成提醒任务直接落 tm.task（source_type=schedule，不经 AI 不进审核，决策 37-1）
  -> 每超期客户一条任务（决策 37-2），N 与逾期判定同参 crm.follow_up_days（决策 37-3）
```

- **依赖**：v0.3 已发版（crm 四表/写接口/转交器/消费者机制/任务中心/任务步骤）。
- **明确不包含**：登录密码/角色（决策 36 撤销，v0.7 权限系统）；权限系统（v0.7）；SEO/扒图/ERP（延后不排期，决策 33）；事件触发/配额记账（用不到就不做，留底座扩展位，决策 33）；高级 cron（每周/每月，v0.4 定时链只支持每天跑，技术定）；AI 设置其余叶子（模型选择/风格指南，占位后续加）。

# 3. sys.settings 表（配置地基，决策 34）

> 住业务库，新 schema `sys`。ORM：`models/sys.py`（复用 TmBase，R22）。

```sql
CREATE SCHEMA sys;
CREATE TABLE sys.settings (
    key         TEXT PRIMARY KEY
                CHECK (key ~ '^[a-z][a-z0-9_.-]{0,63}$'),  -- 域.参数 命名，防注入/防乱键
    value       TEXT NOT NULL DEFAULT '',
    description TEXT NOT NULL DEFAULT '',                 -- 中文说明（设置页展示）
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**说明**：
- **键命名**：`域.参数`，本版键清单见 §7.3 表。
- **value 全 TEXT**，按键类型解析（int / bool / time / str），解析失败回退默认（决策 34 表无回退默认）。
- **读取封装**（web 侧 `web/settings_store.py` 新建 `SettingsStore`，构造注入，生产 from_env）：
  - `get(key, default)`：查表 -> 有则按类型解析返回；无/解析失败 -> 返回 default。
  - 密钥类配置（DeepSeek key / 飞书 webhook URL）**不进 settings 表**（R20），走 .env；settings 表只存非敏感参数。
  - 业务代码一律经 `SettingsStore.get` 取参数，**禁止新增硬编码参数**（验收断言覆盖，§11 A38）。
- 老配置平滑迁移：`.env` 的非密钥参数（无）不动；v0.3 硬编码（FOLLOW_UP_DAYS/page_size）搬表后**默认值与表种子一致**（见 §7.3 种子，不写迁移脚本种数据——首次 get 无键即回退默认，等价；页面保存即落键，技术定）。

# 4. sys.shop 表（店铺管理，决策 33①）

```sql
CREATE TABLE sys.shop (
    id         BIGSERIAL PRIMARY KEY,
    name       TEXT NOT NULL CHECK (length(name) BETWEEN 1 AND 100) UNIQUE,  -- 店铺名唯一
    remark     TEXT NOT NULL DEFAULT '',          -- 备注
    enabled    BOOLEAN NOT NULL DEFAULT TRUE,     -- 启用停用（禁用不出现在 CRM 下拉）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_shop_enabled ON sys.shop(enabled);
```

**说明**：
- 管理页：增（name+remark）/ 改 / 启停 / 删除（二次确认 hx-confirm，物理删；**crm.customer.source_shop 存的是店铺名字符串，不受删除影响**——无 FK，R21）。
- **CRM 客户表单来源店铺改造（决策 37-6）**：`crm.customer.source_shop` 列（TEXT）**不动**；客户新建/编辑表单来源店铺 = **下拉候选（sys.shop WHERE enabled=true）+ 可留空**；选中写入店铺 name 文本。存量自由文本**保留原样显示，不做清洗迁移**（v0.3 从零录数据存量极少，后期人工直接删，决策 37-6）。

# 5. schedule 表（引擎库，定时触发底座，决策 33/技术定）

> 住引擎库。ORM 与现有四表同住 `engine/core/db.py`（R22 同源）。

```sql
CREATE TABLE schedule (
    id           BIGSERIAL PRIMARY KEY,
    chain_id     TEXT NOT NULL,                        -- 引擎注册表已登记链（白名单校验，loader 已加载）
    name         TEXT NOT NULL CHECK (length(name) BETWEEN 1 AND 100),  -- 展示名
    cron         TEXT NOT NULL DEFAULT '0 7 * * *',    -- 5 段 cron；v0.4 仅支持每天 "M H * * *"（技术定）
    enabled      BOOLEAN NOT NULL DEFAULT TRUE,        -- 开关（设置页独立提交）
    last_run_at  TIMESTAMPTZ,                          -- 上次触发时间（幂等锚点，§9.3）
    next_run_at  TIMESTAMPTZ,                          -- 下次计划时间（调度器维护）
    last_status  TEXT NOT NULL DEFAULT ''              -- 上次运行结果摘要（展示用）
                 CHECK (last_status IN ('','done','failed','skipped')),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_schedule_enabled ON schedule(enabled);
```

**说明**：
- **cron 范围（技术定）**：v0.4 只支持每天跑（分/时两段，其余为 `*`），设置页给「每天 HH:MM」选择器生成 cron；表存完整 5 段（为 v0.5 每周/每月留位，届时再加解析库）。
- **新增链白名单**：chain_id 必须命中引擎注册表已登记链（`registry.chains`），否则 422（R7 声明式注册精神）。
- **启动种子（技术定）**：引擎启动时若 schedule 表为空，插入 1 条种子——`crm_reminder_chain`（name=「CRM 未跟进提醒」，**cron 固定 `0 7 * * *`**，enabled=true）。种子 cron 不读 settings（引擎不连业务库；`schedule.default_time` 只用于设置页新建链时预填，两者默认一致均为 07:00）。种子幂等（表非空不插）。
- **next_run_at 计算（技术定）**：cron 限定 daily 形，纯代码算「下一个每天 HH:MM」（>= now 的最小未来时刻）；不引第三方 cron 库。

| GET | /api/biz/settings/engine-params | 引擎启动读 AI 引擎参数（§7.3 engine.* 三键） | -> `{max_attempts, timeout_s, backoff_cap}`（web 侧读 settings 表，缺省回退默认） |

## 9.3 调度器（engine/server.py lifespan 内 asyncio 常驻，技术定）

```text
启动：lifespan 起 asyncio.Task（可注入 clock/interval，测试禁用或桩时钟）
tick 周期：30s
每 tick：
  1) ensure_seed_schedules()（空表种子，§5）
  2) 查 enabled 且 next_run_at <= now 且 last_run_at < next_run_at 的链
  3) 逐条（事务内）：
     a) mark_schedule_run（last_run_at = 本次 next_run_at；next_run_at = 下次每天 HH:MM；last_status=''）
     b) create_task(chain_id, trigger_type='schedule', trigger_ref=str(schedule_id),
                    input={'trigger_date': 今天 YYYY-MM-DD})
  4) 触发异常 -> last_status='failed' 记录（不阻塞其他链；下次 tick 按锚点不再补跑该次）
漏跑补跑（验收「不漏跑」）：引擎 07:00 停机、07:10 起来 -> 07:00 到点未触发（last_run_at < next_run_at <= now）
  -> tick 补触发一次并推进锚点；不重跑（验收「不重跑」）= last_run_at 锚点 + 写接口防重（§8）双保险
立即运行（验收「立即运行」）：POST run 直接入队，与计划互不影响；当天重复触发由写接口防重拦截
崩溃恢复：锚点持久化在引擎库（进程重启读库，不丢）；运行中任务由引擎检查点机制（v0.1/v0.2 已有）续跑
```

- 触发链的 `trigger_date` 由调度器注入（非 created_at），保证手动「立即运行」与计划运行同日去重语义一致（§8 防重键）。

## 10.4 去重语义汇总（验收「同一客户当天重复触发只生成一次」）

| 场景 | 结果 |
|---|---|

| 客户跟进后（last_contacted_at 刷新） | 不再出现在超期清单 -> 不再生成 |

# 13. 决策点

**技术方已定（授权范围内，无异议即执行）：**
- settings 表住业务库 sys schema（web 直读写）；引擎读 AI 引擎参数经 web 只读接口（决策 26 零业务库连接串不破）；schedule 表住引擎库，web 经引擎接口管理（R24 双向 HTTP）
- 调度器在 engine/server.py lifespan 内 asyncio 常驻（tick 30s；可注入桩时钟）；锚点 last_run_at/next_run_at 持久化（漏跑补跑/不重跑）；启动空表种子 crm_reminder_chain
- 提醒链 = 纯代码工序（reason:none，demo_propose 先例）产出 TaskProposal（action_id='tm.schedule'）-> 新消费者直接落 tm.task（复用 server._after_task 分派，server 改动最小）；suggested_role='运营'（决策 11 默认角色）；source.audit_ids 空走 reason:none 豁免
- cron v0.4 仅支持每天（"M H * * *"），next_run 纯代码计算，不引第三方 cron 库
- API 密钥/飞书 webhook 写 .env（R20），保存后重启引擎生效（v0.4 不做热加载）；飞书开关存 settings（notify.feishu_enabled）
- 定时链新增 = 引擎注册表已登记链白名单；定时链不做删除（停用等效）；店铺物理删除（二次确认，source_shop 存文本不受影响）
- 引擎参数读取失败回退默认 + warning 不阻塞启动（决策 34 表无回退默认）

**已拍板（决策 37，2026-08-30 用户确认）：**
1. 提醒任务纯代码生成直接落 tm.task 自动就位（不经过 AI、不进提案审核；source_type=schedule）
2. 每超期客户一条任务
3. 提醒阈值与逾期判定同参 `crm.follow_up_days`（默认 5）；提醒范围 = 与逾期判定同口径（archived 排除，on_hold 含）
4. 定时链默认时间 07:00（系统参数 `schedule.default_time` 可改）
5. 设置页所有登录用户可访问（v0.7 权限系统接手）

8. 通知配置 = 全局总开关（settings）+ 飞书 webhook URL（写 .env）
