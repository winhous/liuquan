## 4. 数据层（业务库迁移 0011）

### 4.1 新表 `scrape.link_record`（链接记录：一个链接一条）

```sql
CREATE TABLE scrape.link_record (
  id            BIGSERIAL PRIMARY KEY,
  url           TEXT NOT NULL,                      -- 原始分享链接（含 xsec_token/id 等 query）
  normalized_url TEXT NOT NULL,                     -- 规范化链接（去 xsec_token 等易变 query），查重键
  source        TEXT NOT NULL CHECK (source IN ('xhs','xianyu','http')),
  status        TEXT NOT NULL DEFAULT 'pending'
                CHECK (status IN ('pending','downloading','done','failed')),
  image_count   INT NOT NULL DEFAULT 0,             -- 成功落库图片数
  desc          TEXT DEFAULT '',                    -- 商品描述（元数据）
  tags          JSONB NOT NULL DEFAULT '[]',        -- 标签
  author_id     TEXT,                               -- 作者/卖家 ID
  batch_id      TEXT NOT NULL,                      -- 批次（立即扒=web uuid；定时=sched-<ts>）
  storage_dir   TEXT,                               -- 落盘相对路径（相对 scrape.storage_dir）
  error_note    TEXT,                               -- 失败原因（未落盘/xsec_token 过期/选择器失效/超时/失效页…）
  degraded_note TEXT,                               -- 元数据降级原因（db-missing/no-title/no-seller-id/…，空=全量读到）
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (normalized_url)                           -- 一链接一条（同作品不同 token 幂等）
);
CREATE INDEX idx_scrape_link_status_created ON scrape.link_record(status, created_at DESC);
CREATE INDEX idx_scrape_link_batch ON scrape.link_record(batch_id);
```

> 设计说明：**一链接一条记录**（拍板 A）。`normalized_url` = url 去掉易变 query（xsec_token）后的规范化串，重复粘贴同作品（token 已过期重取）不重复建记录。**防重**：同 url 重复提交返回现有记录（幂等语义），不重复下载。

## 5. 引擎侧设计（拆两链 + 链路修复）

### 5.1 拆两链（T1/T2/T6）

```yaml
# scrape_download_chain（贴链接：立即扒 / 定时扒共用）
# input: ScrapeChainInput{urls[], batch_id, source?, from_queue=false}
#   - 立即扒：urls 填满，from_queue=false
#   - 定时扒：urls 空，from_queue=true（urls 从队列读，§5.4）
id: scrape_download_chain
domain: scrape
input: ScrapeChainInput
steps:
  - worker: link_record_create     # 建链接记录（幂等；from_queue 时经 provider 读队列）
    input: {urls: task.input.urls, batch_id: task.input.batch_id, from_queue: task.input.from_queue}
  - worker: batch_image_download   # 逐链接：connector 下载 → 图片体检（内联 PIL）→ 图片落库（挂链接）→ 更新链接记录
    input: {link_ids: steps[0].output.link_ids, batch_id: task.input.batch_id}
# 链完成 → 消费者 scrape.download_done（deliverable = ScrapeBatchResult，from_queue → 清队列）

# scrape_suggest_chain（勾图选品，瘦身为单步）
id: scrape_suggest_chain
domain: scrape
input: SuggestionInput        # {image_ids[], batch_id?, target_keywords?}（原契约不变）
steps:
  - worker: product_suggestion    # 诚实化：真接 LLM（§5.2 T5）
# 链完成 → 消费者 scrape.suggest（已有：提案 → tm.task_proposal pending）
```

> **2026-09-03 批 4 前修正（铁律 2 先改详设）**：下载链改为 **2 步**（link_record_create → batch_image_download），体检（宽高/水印 PIL）**内联在 batch_image_download**（下载时本地路径在手，一次写接口带回 width/height/watermark/source_mark，避免中间产物回读）；`image_inspect` worker 保留为**独立工序**（修通：经 ctx.biz_client 读 local_path + 写体检，供「重新体检」等独立场景，A67 走 worker 级测试），下载链不再引用。链末产出 = **ScrapeBatchResult**（消费者 scrape.download_done 接收类型与链末输出一致，消除 §5.3 原矛盾）。
