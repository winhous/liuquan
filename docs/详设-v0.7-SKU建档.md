## 0. 一句话

**建档 = 建"货档案"**。三种档案：**实物档案**（真 SKU：仓库里采购来的一件货，如 红机/蓝机/普通盒/精装盒/珍珠螺/杯腿，有库存有成本）/ **组合档案**（组合编码：如 精装红 = 红机×1+精装盒×1、珍珠螺炫彩杯 = 珍珠螺×1+杯腿×1——Etsy 填一个"SKU"框，系统里**不是真 SKU，是配方**，BOM 展开扣子件库存）/ **定制档案**（CUSTOM 占位：无库存、接单生产）。"打火机/水晶玫瑰"这类名 = 档案上的**归类文本（商品名）**，不是实体。Etsy 变体框填的编号 = 档案编号，零映射；订单回来实物直扣、组合展开扣。

### 1.2 用户确认的模型要点（逐条出处见 §14 M1-M12）

1. **没有"品实体"**：建档 = 建货档案；"打火机"只是商品名归类文本（M1/M4）
2. **三种档案**：physical（真 SKU，有库存）/ combo（组合编码+配方，无库存）/ custom（定制占位，无库存）（M2）
3. **精装红 = 一个可售档案**（combo），不是两个 SKU；配方引用的红机/盒是别的实物档案（M3）
4. **手工加档**：无变体框架、无自动展开、无推荐；商品名下逐档自己建（M5）
5. **编号自由填 + 查重 + 格式校验**，Etsy 框直接填，零映射（M6）
6. **图 = 档案图库 + 店级使用**：建档收图（素材库挑/自己上传）；图不自动继承；选图软提示"已在哪平台哪店用过" + 二次确认不强制（M7/M8）
7. **随机/任选档不做自动机制**：普通档案，出库人工基于真实库存填实发（M9）
8. **建库存表**（warehouse/stock/stock_ledger），建档不填库存数字（M10）
9. **不做生产**（工单后置，随时可接；珍珠螺炫彩杯 = combo 固定配方即够）（M11）
10. CUSTOM 定制占位：无库存、成本可空、接单生产（M12）

## 2. 模型定义（思维基准）

### 2.1 三种货档案

| | physical 实物档案 | combo 组合档案 | custom 定制档案 |
|---|---|---|---|
| 是什么 | 真 SKU：仓库里的一件货 | 组合编码：配方组合出的可售单元 | 定制占位：接单生产 |
| 例 | 红机、蓝机、普通盒、精装盒、珍珠螺、杯腿 | 精装红 = 红机+精装盒；珍珠螺炫彩杯 = 珍珠螺+杯腿 | CUSTOM-BQ 定制花束 |
| 库存 | ✅ 有（×仓库，跨店唯一锚） | ❌ 无（BOM 展开扣子件） | ❌ 无 |
| Etsy SKU 框填 | 本档案编号（LTR-RED） | 本档案编号（COMBO-...） | 本档案编号（CUSTOM-...） |
| 订单对库存 | 直扣 | BOM 展开逐子件扣（两段式 §3.7） | 转人工接单（v0.9） |

**实物档案是"跨店同款"的唯一锚**：店1/店2 引用同一实物档案 → 查它被哪些店的哪些 listing 引用即得跨店视图（品实体想干的事，实物档案天然干了）。

### 2.2 商品名 product_name（归类文本）

- item 上一个**文本字段**（可空），如：打火机 / 水晶玫瑰
- 作用：建档时"商品名 + 逐档添加"的组织入口；列表按商品名聚合；同款识别（展示层）
- **不背任何字段**：不变体框架、不图、不价格、不 SEO（M4）

### 2.3 编号 code

- 规则：**自由填 + 全库唯一 + 格式校验**（数据底层逻辑 §3.7 拍板）；系统不做自动建议（用户不要推荐，M6）
- 格式：`^[A-Za-z0-9_-]{1,40}$`（禁逗号/斜杠/空格/中文，Etsy 官方规则，调研 F2）——接口 + DB CHECK 双层
- 建议前缀（**非强制**）：combo 建议 `COMBO-`、custom 建议 `CUSTOM-`，便于订单两段式识别；physical 自由

### 2.4 图：档案图库 + 店级使用足迹（软提示，不强制）

```
建档收图（从素材库挑已有图 / 自己上传新图）→ 挂档案图库（item_image）
图不自动继承到任何店（店级各挑各的）
某图在某店用了 → 人工登记足迹（image_shop_usage：图 × 店，平台从 sys.shop 读）
选图/建档时 → 该图足迹可见："已在 Etsy-店1 用过"
复用已用过的图到另一店 → 软提示 + 用户二次确认 → 放行（不强制）
```

- 同图同平台不重复 = **提示辅助人工判断**，不做硬拦截（用户拍板：现阶段不强制，将来要强制再收紧）
- 自己上传的图 = 新建 scrape.image_file 行（source_mark=selfshot 或 authorized，v0.7 简单化：selfshot）+ 落盘 → 再挂图库；上传图也进素材库体系（可被其他档案引用）

### 2.5 库存（M10：建表，建档不填数字）

- 库存 = physical 实物档案 × 仓库；combo/custom 无库存行
- 建档/上架**不校验库存**（接单采购模式：绝大多数不备货、部分备货；库存不影响销售，数据底层逻辑 §2.2/§2.5）
- 流水五类必记（sale/purchase/loss/adjust/return）；v0.7 手工可记 purchase/loss/adjust/return，sale = 501（v0.9 订单回流开闸）
- 对不上账按流水追溯（谁、何时、为何，§2.4）

### 2.6 随机/任选（M9：不做自动）

- Etsy 侧照常一个编码可售；系统里 = 普通档案（combo 或 physical），**无候选集×数量的自动随机机制**
- 出库：人工基于真实库存填实发（发蓝扣蓝、发 5 黄扣 5 黄）——"人工指定实发"是出库通用能力（换货/补发/差异都靠它）
- 多样性软提示（可选增强，后置）：仅当 listing 文案声明"不同颜色"时出库软提示一次，不强制

### 2.7 不做生产（M11）

- 珍珠螺炫彩杯 = combo 固定配方（珍珠螺×1+杯腿×1）即覆盖"采购件组合成可售物"
- 生产工单/组装/在制品 = 独立大域，后置；combo+BOM 结构已让将来能挂生产而不返工

## 3. 数据层设计（业务库迁移 0013，schema `catalog`）

> 迁移文件：`migrations/business/versions/0013_create_catalog_skus.py`
> ORM：新 `models/catalog.py`（复用 models/tm.py 的 TmBase，R22 同源）
> 设计原则：编号查重/格式、kind 类型、combo 配方只引用 physical、库存只 physical、流水必记——全部进写接口校验（§8），DB 层 CHECK/UNIQUE 兜底（数据库是最后防线）

### 3.1 表总览（7 表 + sys.shop 加列）

```text
catalog.item               货档案（physical/combo/custom 三型；核心表）
catalog.item_bom           combo 档案的配方行（parent=combo，child=physical，qty）
catalog.item_image         档案图库（item × scrape.image_file 引用，不复制文件）
catalog.image_shop_usage   图店使用足迹（image_file × sys.shop，平台 join）
catalog.warehouse          仓库（迁移种子：代发仓 / 自有仓）
catalog.stock              库存 = 实物档案 × 仓库
catalog.stock_ledger       库存流水（sale/purchase/loss/adjust/return，必记）
sys.shop（既有）           + platform 列（平台：etsy/xianyu/xhs/other）
```

### 3.2 `catalog.item`（货档案，核心表）

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| code | TEXT | **NOT NULL + UNIQUE** + CHECK 格式 | 编号 = Etsy SKU 框值；格式 `^[A-Za-z0-9_-]{1,40}$`（禁逗号/斜杠/空格/中文）；全库唯一 |
| name | TEXT | NOT NULL，长度 1..120 | 档名（红色 / 精装红 / 珍珠螺炫彩杯） |
| product_name | TEXT | NULL，长度 1..120 | **商品名归类文本**（打火机）；可空（纯采购件可无） |
| kind | TEXT | NOT NULL CHECK IN ('physical','combo','custom') | 档案类型 |
| cost | NUMERIC(12,2) | NULL | 成本（可空后补）；combo 可空；custom 可空 |
| supplier | TEXT | NULL | 采购来源（接单采购触发参考） |
| status | TEXT | NOT NULL DEFAULT 'active' CHECK IN ('active','delisted') | 生命周期简化两态：在售 / 下架（档案保留可恢复）；停产等后续按需加 |
| remark | TEXT | NOT NULL DEFAULT '' | |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

表级：`UNIQUE(code)`；CHECK 格式；索引 `(product_name)`（同款聚合）、`(kind)`。
应用层（接口）：建档即 active（无 drafting 中间态，无保存草稿）；删除仅限无任何下游引用（无 stock 行/流水/图库/BOM 行/足迹），有业务数据只能 delisted（档案保留）；同商品名下允许同名档？——**不允许**（同 product_name + 同 name 冲突 409，防手滑重复建）；code 建议前缀不强制。

### 3.3 `catalog.item_bom`（combo 配方行）

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| parent_item_id | BIGINT | NOT NULL FK→catalog.item.id ON DELETE CASCADE | 父 = combo 档 |
| child_item_id | BIGINT | NOT NULL FK→catalog.item.id ON DELETE RESTRICT | 子 = physical 档（红机、精装盒） |
| qty | NUMERIC(10,3) | NOT NULL DEFAULT 1 CHECK > 0 | 数量（可小数，如耗材 0.5） |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

表级：`UNIQUE(parent_item_id, child_item_id)`；索引 `(child_item_id)`（反查被哪些组合引用）。
应用层：parent.kind='combo'、child.kind='physical'（配方只引用实物档案；不组合套组合——嵌套 = 卖法层套餐 v0.8）；不自引用；active 档禁改 BOM（改配方 = 下架→编辑→上架，变更日志留痕）。

### 3.4 `catalog.item_image`（档案图库）

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| item_id | BIGINT | NOT NULL FK→catalog.item.id ON DELETE CASCADE | 档案 |
| image_file_id | BIGINT | NOT NULL FK→scrape.image_file.id ON DELETE RESTRICT | 引素材库图（含自己上传新建的） |
| is_main | BOOLEAN | NOT NULL DEFAULT false | 主图标记（应用层：每档案至多一张） |
| sort | INT | NOT NULL DEFAULT 0 | 排序（小在前） |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

表级：`UNIQUE(item_id, image_file_id)`；索引 `(image_file_id)`。
应用层：一张图可被多个档案图库引用（红机图 ≠ 打火机场景，人工把关）；**多主体图不挂**（建档选图人工把关，v0.7 无机器检测）。

### 3.5 `catalog.image_shop_usage`（图店使用足迹）

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| image_file_id | BIGINT | NOT NULL FK→scrape.image_file.id ON DELETE RESTRICT | 图 |
| shop_id | BIGINT | NOT NULL FK→sys.shop.id ON DELETE RESTRICT | 店铺（platform 从 sys.shop join 展示） |
| note | TEXT | NOT NULL DEFAULT '' | 备注（如"店1 打火机 listing 用"） |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

表级：`UNIQUE(image_file_id, shop_id)`；索引 `(shop_id)`。
语义：**登记 = 人工动作**（v0.7：手工上架 Etsy 后登记"此图已用于该店"）；选图接口返回足迹列表供软提示（"已在 Etsy-店1 用过"）；**同图同店只记一次**（重复登记幂等或 409）。

### 3.6 `catalog.warehouse` / `catalog.stock` / `catalog.stock_ledger`

**warehouse**：

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| name | TEXT | NOT NULL UNIQUE（长度 1..60 CHECK） | 代发仓 / 自有仓 |
| remark | TEXT | NOT NULL DEFAULT '' | |
| enabled | BOOLEAN | NOT NULL DEFAULT true | 停用后不可记新库存 |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

种子（迁移 upgrade 幂等 INSERT，照 v0.4 seed 风格）：代发仓、自有仓。

**stock**：

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| item_id | BIGINT | NOT NULL FK→catalog.item.id ON DELETE RESTRICT | 只 physical（接口校验） |
| warehouse_id | BIGINT | NOT NULL FK→catalog.warehouse.id ON DELETE RESTRICT | |
| qty | NUMERIC(14,3) | NOT NULL DEFAULT 0 CHECK qty >= 0 | 备货记数，不备货无行 |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

`UNIQUE(item_id, warehouse_id)`；不备货 = 无行（首次入库/调整时建行，接口统一处理）。

**stock_ledger**：

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK autoincrement | |
| item_id | BIGINT | NOT NULL FK→catalog.item.id ON DELETE RESTRICT | |
| warehouse_id | BIGINT | NOT NULL FK→catalog.warehouse.id ON DELETE RESTRICT | |
| change_type | TEXT | NOT NULL CHECK IN ('sale','purchase','loss','adjust','return') | 五类；sale v0.7 501 |
| qty_delta | NUMERIC(14,3) | NOT NULL CHECK <> 0 | 正入负出 |
| before_qty / after_qty | NUMERIC(14,3) | NULL（接口写快照） | 追溯 |
| ref_type / ref_id | TEXT / BIGINT | NULL | 关联单号（v0.9 订单/采购单） |
| operator | TEXT | NOT NULL DEFAULT 'web' | 操作人（v1.0 前角色名/'web'/'engine'） |
| note | TEXT | NOT NULL DEFAULT '' | 原因 |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

索引 `(item_id, created_at)`、`(change_type, created_at)`。
**一致性铁律**：任何库存数量变动 = 一条流水（同事务：读→校验→快照 before/after→写 stock→写 ledger）；只允许经 §8 写接口发生，页面/引擎不得直改。

### 3.8 迁移与 ORM（含跨 schema FK 注册要求，子代理必读）

- 迁移 0013：CREATE SCHEMA `catalog`（若不存在）+ 7 表 + 约束/索引 + 两仓种子 + sys.shop 加 platform；downgrade 逆序 DROP（item_bom → item_image → image_shop_usage → stock_ledger → stock → item → warehouse → schema；sys.shop.platform 用 drop_column）
- `models/catalog.py`：Item/ItemBom/ItemImage/ImageShopUsage/Warehouse/Stock/StockLedger 7 ORM
- **⚠ 跨 schema FK 注册要求（技术定）**：item_image.image_file_id → `scrape.image_file.id`、image_shop_usage.shop_id → `sys.shop.id` 是**本项目首批跨 schema FK**。SQLAlchemy `ForeignKey("scrape.image_file.id")` 解析要求目标表已注册进 TmBase.metadata——而 `models/sys.py` **至今未注册**（env.py 只 `from models import crm/scrape`；0006 建 sys 表是手写迁移，非 metadata 驱动）。因此：
  - `models/catalog.py` 顶部 `from models import sys as _sys_reg` + `from models import scrape as _scrape_reg`（import 副作用注册 FK 目标表）

## 4. 建档流程（手工加档）

### 4.1 建档交互（用户拍板：无自动展开、无推荐，自己在商品名下逐档加）

```
入口（双入口，§4.2）
  → 表单：商品名（可空，如"打火机"；已存在则下拉选，输入新名=新归类）
  → 逐行加档（一次表单可加多行，也可先建一行后面再加）：
       档名（红色）/ 类型（默认 physical）/ 编号 code / 成本（可空）/ 采购源（可空）
  → 类型 combo 的行：展开配方编辑器——选子件实物档案 × 数量（精装红 → 红机×1 + 精装盒×1）
  → 类型 custom 的行：无配方无库存（定制占位）
  → 提交 → 写接口校验（编号格式/查重/同商品同名档冲突/配方子件 physical…）→ 落库（全部 active）
```

**边界规则**：
- 建档**一次可多档**（同商品名下）；之后可在档案列表/详情"加档"（换商品名或同商品继续加）——**"打火机"下想加蓝档就进打火机的档列表加一行**
- 建档**不要求先有图**（老货可后补图，接缝预留）；建档时可选收图（§5）
- 子件档案必须先建（combo 引用已存在的 physical 档案）——先建红机/精装盒，再建精装红
- 定制（custom）：无 BOM 无库存，成本可空；可作为"定制花束"单档建档（商品名可空或"定制花束"）

### 4.2 建档入口（双入口）

1. **素材库选图建档**：素材库页按图勾选（跨链接）→「用所选图建档」→ 建档表单预载图（图在提交后挂档案图库）——**链接行不设"建档"按钮**（一个链接含多商品，图才是选择单位，M 讨论确认）
2. **SKU 页「新建档案」**：空表单 + 「从素材库选图」弹层（按链接/缩略图浏览勾选，可跨链接混选）

### 4.3 页面路由（web 侧）

| 路由 | 功能 | 数据 |
|---|---|---|
| `/skus` | SKU 建档页 = 档案列表 | 按商品名分组 + 档行（编号/类型/成本/状态）；新建入口 |
| `/skus/new` | 建档表单（商品名 + 多行档 + combo 配方 + 选图） | 建档提交 |
| `/skus/{item_id}` | 档案详情：基本信息 + 配方（combo）+ 图库（挂图/足迹/登记用店）+ 状态操作 | |
| `/skus/{item_id}/inventory` | 库存页：各仓库存 + 流水按钮 | 记数/流水列表 |
| `/skus?product_name=` | 同款聚合视图（按商品名过滤） | |

> **导航归属**：MODULES 一级数组在 workspace 之后、tm 之前插入 `{"id":"skus","name":"SKU 建档","icon":"ti ti-box","href":"/skus",...}`；**登录保护**：/skus* 照 /settings 模式中间件守卫（未登录 303 /login）。样式照 Tabler，功能优先样式后调（决策 18）。

### 4.4 编号规则

- 见 §2.3：自由填 + 格式 `^[A-Za-z0-9_-]{1,40}$` + 全库唯一（接口 409 + DB UNIQUE）；无自动建议
- 建档表单编号留空 → 校验报错（必填）——不强推建议，但可在页面上提示建议前缀约定（COMBO-/CUSTOM-）

### 4.5 状态与删除

- status 两态：active（在售）/ delisted（下架，档案/图/流水保留，可恢复 active）
- 状态转换只经写接口；删除仅限无任何下游引用（无 stock/流水/图库/BOM/足迹），有数据只能 delisted

## 5. 库存与流水（M10 落地：建表，建档不填数字）

### 5.1 记账模型

- stock 行 = physical 实物档案 × 仓库；combo/custom 无行（写接口 409）
- 建档/上架**不读库存**（接单采购：不阻塞销售；库存作用 = 备货提醒/售出采购触发/报表，数据底层逻辑 §2.2/§2.5）
- 多仓：代发仓/自有仓（种子）；组合展开扣减按子件各自库存行扣（v0.7 不做仓库策略，v0.9 定）

### 5.2 流水规则（五类，v0.7 手工入口）

| change_type | 方向 | v0.7 手工入口 | 说明 |
|---|---|---|---|
| purchase 采购入库 | + | ✅ 入库按钮 | 到货入库（选仓+qty+note） |
| adjust 调整 | ± | ✅ 调整按钮（必填原因） | 盘点/纠错 |
| loss 报损 | - | ✅ 报损按钮（必填原因） | 损坏/丢失 |
| return 退货入库 | + | ✅ 退货按钮 | 买家退货 |
| sale 销售扣减 | - | ❌ 501（v0.9 订单回流） | — |

- 每次变动 = 同事务：读当前 qty → 校验（physical、qty>0、qty+delta ≥ 0）→ 快照 before/after → 写 stock → 写 ledger
- 流水只增不可删改；纠错 = 反向 adjust

### 5.3 页面交互（库存页）

- 每档：各仓库存数字 + 操作按钮（入库/调整/报损/退货）+ 流水查看
- 表格：档 × 仓库矩阵；操作弹小表单；全部走 §8 写接口

## 6. 图与足迹（档案图库 + 软提示）

### 6.1 挂图

- 建档提交时可带 image_file_ids → 自动挂档案图库；之后档案详情可继续挂/撤
- 来源：①素材库已有图（scrape.image_file，带 source_mark 来源标记）②**自己上传**——上传接口建新 image_file（source_mark='selfshot'，落盘 scrape 存储体系）→ 挂图库
- 一张图可被多档案引用（人工把关）；同档不重挂（UNIQUE）；多主体图人工不选

### 6.2 足迹登记与软提示

- **登记**：档案详情图库每张图 →「标记已用于店铺 X」（下拉选 sys.shop）→ 写 image_shop_usage（同图同店幂等）

- 同店重复登记 = 幂等忽略（或提示已登记）

### 6.3 素材来源与来源标记

- 图只来自 scrape.image_file（v0.6 素材库产物，source_mark 四值 scraped/selfshot/ai_generated/authorized 防侵权 §3.3）
- 挂图不改来源标记；上传图默认 selfshot（人工可改 authorized 等——**技术定：上传接口带 source_mark 可选参数，默认 selfshot**）

## 8. 写接口契约（`/api/biz/catalog/*` + `/api/biz/inventory/*`）

> **写入唯一校验通道**（决策 26 + 用户强调）：人（页面，登录会话）与 AI（引擎，X-Biz-Token）**双通道、同一份 service 校验**（§8.4 清单只实现一次）；页面禁止直写 DAO 绕过校验（A86 代码级断言锁）。实现：`web/catalog_service.py`（★业务校验唯一实现）+ `web/catalog_store.py`（读 DAO）+ `web/api_biz.py` 增两组 handler。

### 8.1 `catalog` 组（建档/图/足迹域）

### 8.3 引擎侧调用约定

- v0.7 引擎零改动、无新链无新工序（建档/库存 = 人工 + 页面 + 写接口域）
- 接口按"引擎可调"设计（X-Biz-Token 通道 v0.3 已建）：v0.9 订单回流 sale 流水直接调本组接口——将来 AI/引擎写数据不需要新增通道，只加权限位
- sale 类型流水 v0.7 统一 501（service 抛 NotImplemented；页面无 sale 表单）

### 8.4 接口统一校验清单（写接口全部执行，单测逐条覆盖）

1. **编号**：必填；格式 `^[A-Za-z0-9_-]{1,40}$`；全库查重（409「编号已被占用」）
2. **档结构**：name 非空 ≤120；kind ∈ 三型；同 product_name + 同 name 冲突 409
3. **combo 配方**：parent.kind=combo、child.kind=physical、qty>0、不重复、不自引用、子件档案存在
4. **custom**：无 BOM 无库存（custom 挂 BOM 409 / 记库存 409）
5. **库存**：只 physical；qty>0；变动后 stock ≥ 0；流水必记（事务原子）；sale=501
6. **图**：image_file 存在；同档不重挂；上传 source_mark ∈ 四值（默认 selfshot）
7. **足迹**：图存在、店存在（enabled）；同图同店幂等
8. **状态机**：active↔delisted；删除守卫（无下游引用才可删）
9. **写权限**：页面会话 / 引擎 token 二选一

> 校验实现统一收敛 `web/catalog_service.py`（页面路由与 api_biz 共用同一函数 → 人和 AI 校验一致，决策 26 + R21）。
